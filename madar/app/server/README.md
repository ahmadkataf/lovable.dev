# مَدار — الخادم (Cloudflare Worker + Durable Object SQLite)

خادم منصّة «مَدار» التجريبية لمديرية تربية درعا: واجهة برمجية تحت `/api/*` (Hono + قاعدة SQLite داخل Durable Object)، ويقدّم واجهة التطبيق المبنيّة من
`../client/dist` كملفّات ثابتة. المواصفة الكاملة في `madar/docs/mvp-spec.md`.

## التشغيل محلياً (باختصار)

```bash
npm install            # يستخدم legacy-peer-deps تلقائياً (.npmrc)
npm run db:apply       # مع تشغيل dev: يطبّق schema.sql ثم seed.sql عبر /api/admin/sql (بيانات اليوم)
npm run dev            # http://localhost:8787 — يحتاج ../client/dist (ابنِ العميل أولاً)
npm run dev:api        # الواجهة البرمجية فقط من دون العميل (ملفّات ثابتة بديلة)
npm test               # اختبارات vitest (المحرّك، الرموز، المسارات، ثوابت البيانات التجريبية على SQLite في الذاكرة)
npm run smoke          # اختبار دخان كامل على wrangler dev --local
```

البيانات التجريبية تُحسب بالنسبة إلى **يوم العرض**: اليوم إن كان يوم دراسة، وإلّا الخميسُ الذي قبله (الجمعة والسبت عطلة). لوحتا المديرية والمدرسة تفتحان على يوم العرض
افتراضياً (ومع `?date=` على أيّ يوم). على يوم جديد أعد تهيئة البيانات: `npm run db:reset` (الخادم نفسه يعيدها كلّ صباح في السادسة بتوقيت دمشق).
الرسائل النصّية في نسخة العرض **محاكاة**: تُحسب لأولياء الأمور الذين لم يفتحوا التطبيق، وتُسجَّل في سجلّ الخادم فقط، وكلّ نصّ يذكرها يقول «(محاكاة في نسخة العرض)».

# Madar server — English reference

Cloudflare Worker (TypeScript, Hono) with a SQLite-backed Durable Object database (src/do.ts + src/dbshim.ts expose it with a D1-shaped API). API under `/api/*`; every other path is served from the
built client (`[assets]` binding, `run_worker_first = true`) with an SPA fallback to `index.html` for paths without a
file extension. Spec: `madar/docs/mvp-spec.md` (§3–6, §8, §9, §11 are implemented here).

## Layout

```
package.json  wrangler.toml (§9)  wrangler.local.toml (API-only dev: stub assets)
schema.sql    seed.sql (generated by scripts/gen-seed.mjs — edit the generator, not the SQL)
src/index.ts        Hono app, CORS, error → {error: "<Arabic>"}, assets fallback, cache rules
src/worker.ts       Worker entry: fetch, the Durable Object class, the 06:00 Damascus reseed + warm-up
src/auth.ts         HMAC-SHA256 tokens (Web Crypto), login rate limit, requireAuth(...roles)
src/scope.ts        who may see which section / student / teacher
src/substitute.ts   §6 engine: pure rankCandidates/suggest + runEngine/ensureSubstitutions (database), suggestionNote
src/notify.ts       notification fan-out (dedupe_key aware) + the SMS simulation ('[SMS]' log lines, counted)
src/stats.ts        dashboard numbers (day status per student, per-school stats, three-day absences, week aggregates)
src/csv.ts          UTF-8 BOM CSV
src/routes/{common,teacher,student,parent,school,directorate}.ts
test/               vitest: substitute, auth, routes, ratelimit, util, seed (+ d1.ts: D1-shaped shim over node:sqlite)
scripts/smoke.sh    end-to-end smoke against wrangler dev --local (port 8787), reseeds at the end and times it
```

## Local development

```bash
npm install                 # .npmrc sets legacy-peer-deps (wrangler 4 ↔ @cloudflare/workers-types peer range)
npm run dev                 # wrangler dev --local on :8787 (ADMIN_KEY=dev), serves ../client/dist  (build the client first)
npm run dev:api             # same Worker with a stub assets folder (scripts/assets-stub) — no client build needed
npm run db:apply            # with dev running: schema.sql + seed.sql through POST /api/admin/sql (key «dev»)
npm run db:reset            # with dev running: POST /api/admin/reseed (drops every table, schema + seed, warm-up)
npm test                    # vitest, no network, no workerd (routes run against schema+seed in an in-memory SQLite)
npm run typecheck           # tsc --noEmit
npm run smoke               # scripts/smoke.sh: fresh local Durable Object DB, logs in as every role, GETs + one POST per role, reseeds
npm run seed:gen            # regenerate seed.sql from scripts/gen-seed.mjs (about one second)
```

`schema.sql` only adds tables (`CREATE TABLE IF NOT EXISTS`): after pulling a schema change into an existing local state,
run `npm run db:reset` (the reseed drops everything first). `TOKEN_SECRET` defaults to `dev-secret` when unset (put a real one
in `.dev.vars` locally or `wrangler secret put` in production). The Vite dev server of the client proxies `/api` to `http://localhost:8787`.

## Authentication (§4)

`POST /api/login {code}` → `{token, user, context}`. Token = `base64url(JSON {uid, role, exp}) + "." + base64url(HMAC-SHA256)`,
`exp` in unix seconds, 30 days. Send `Authorization: Bearer <token>`. Login is limited to 20 attempts per IP per 10 minutes
(in memory, and durably in the database object). Every route checks role and scope; every write is recorded in
`audit_log (user_id, action, target)`. Personal phone numbers are never returned by any endpoint; the directorate sees the
**school** phone (`schools.phone`) and the principal's name.

## Dates

Dates are `YYYY-MM-DD` in Damascus time; day 0 = الأحد … 4 = الخميس. The management views (school dashboard, directorate
dashboard, school page, reports) default to the **report day** = today, or on Friday/Saturday the Thursday before
(`reportDate()` in util.ts); the demo seed anchors every story to that day, so the dashboards are never empty on a
weekend demo. The home screens (teacher, student, parent) still default to today; pass `?date=` to show another day.

Notification `kind`s: `homework`, `absence` (guardian; `sms` flips to 1 on confirmation), `absence_teacher` (school
account, from the engine), `substitution` (the substitute, with the lesson note), `change` (students + guardians,
«تغيّر معلّم الحصّة الثالثة اليوم», or the self-study note), `announcement`, `circular`, `message`, and for directorate
users `no_attendance`, `uncovered`, `three_days` (one per day, kind and school/student — `notifications.dedupe_key`,
`INSERT OR IGNORE`, so refreshing never duplicates; link `/directorate/school/:id?date=`).
`link` values: `/homework/:id`, `/attendance?date=YYYY-MM-DD&student_id=N`, `/absences/:id`, `/substitutions/:id`,
`/timetable?date=…`, `/announcements/:id`, `/messages/:user_id`, `/directorate/school/:id?date=…` — hints for the client.
Long titles and lesson notes are shortened for the bell at a word boundary with «…» (`ellipsize`, never mid-word).

"Day status" of a student = status of the first recorded period of that day (`present`/`late` count as present in the
percentages). Alerts: `no_attendance` (school day, nothing uploaded), `uncovered` (suggested rows not yet approved /
self-study), `three_days` (absent on three or more consecutive school days, counting back from the report date; days with
no upload at all are skipped).

## SMS simulation

The gateway is phase 2. The pilot's SMS would reach guardians who have a phone and have never opened the app (no `login`
in `audit_log`); the demo version only logs those as `console.log('[SMS]', phone, body)` and reports the count. Every
user-visible string that mentions text messages carries «(محاكاة في نسخة العرض)». The `sms` flag on `notifications` keeps
its meaning («eligible for SMS»); the simulated count is the subset whose recipient has no app.

## Substitute engine (§6)

`src/substitute.ts`: `rankCandidates(slot, ctx)` / `suggest(slots, ctx)` are pure. Eligible = same school, free at that
day/period, not absent that date, not already assigned at that period, and `weekly periods + substitutions this week <
WEEKLY_CAP` (env, default 28). Tier 1 same subject, tier 2 teaches the section, tier 3 others; within a tier fewer
approved substitutions this month, then fewer weekly periods, then name. Reasons are neutral: «المادّة نفسها · حصّة فراغ ·
بلا تعويضات هذا الشهر», «من معلّمي الشعبة · حصّة فراغ · …», «حصّة فراغ · …». The top 3 are stored as `candidates`, the
first as `substitute_teacher_id`, status `suggested`; with nobody free `candidates=[]` and `no_candidate=true`. Every
suggested row carries `note`: `null` when a same-subject teacher heads the list, otherwise «لا معلّم {المادّة} متاحاً في
هذه الحصّة، فاقتُرح معلّمون من مواد أخرى» (or «لا معلّم متاحاً في هذه الحصّة — تعلّم ذاتي موجَّه» with nobody at all).
The school account is notified «غياب أ. … اليوم: N حصص بحاجة إلى تغطية» for the periods the engine had to open.
`runEngine` is idempotent (`INSERT OR IGNORE`); `ensureSubstitutions(date)` runs it for absences that still have an
affected period without a row — the seeded absences arrive with their morning periods decided and the last ones open.

## Seed (§8, round 2) — `seed.sql`, idempotent, generated by `scripts/gen-seed.mjs`

Ten schools of the Daraa governorate (neutral names, synthetic principals and `0955…` school phones): درعا النموذجية
(درعا المدينة), إزرع الأولى, طفس الثانية, نوى الأولى, الصنمين المختلطة, جاسم الثانية, الحراك الأولى, بصرى الشام الأولى,
داعل, المزيريب — 91 sections, ≈ 2 630 students (200–360 per school, 25–33 per section), ≈ 1 830 guardians (70 % of the
students; ≈ 55 % of the guardians have opened the app), 138 teachers (12–18 per school), 2 730 timetable rows, ≈ 68 000
attendance rows, ≈ 500 KB of SQL, under half a second to apply.

Schools 1–3 keep the round-1 demo accounts, sections and ids. School 1 has the pitch's three sections (الخامس (أ), الخامس
(ب), السادس (أ), 28 students each, the first twelve as before) built by the anchored search (الخامس (ب) on Thursday = عربي،
رياضيات، علوم، إنكليزي، دراسات، رياضة; سامر free Thu P5; ماهر free Thu P3) plus eight "block" sections. A block is four
sections that share six teachers (one per subject); its week is one 30-slot sequence read with a different offset by each
section, so quotas hold (7/6/4/5/4/4) and no teacher is double-booked. ماهر عادل also teaches science to school 1's second
block (20 periods a week), and every weekday رنا has a period in which he is free.

The demo day (= report day) is prepared: رنا سعيد absent (approved → ماهر, the other period approved or self-study), a
second absence in school 1 whose last two periods wait for the principal; six pending periods in four schools in all (the
engine ranks their candidates on the first dashboard load or at the reseed warm-up) → ≈ 85 % coverage governorate-wide;
school 8 (بصرى الشام الأولى) has not uploaded attendance; attendance ≈ 90 % with جاسم الثانية at ≈ 80 %; يزن عماد (الخامس
(أ)) absent three consecutive school days; the four school days before carry confirmed six-period attendance and one or
two decided absences per school (a few periods left uncovered) so the weekly report has data. Attendance absences are a
per-student hash with a step that makes three-day streaks impossible except the intended one. Notifications the day would
have produced are seeded too (school accounts, substitutes, affected sections, the guardians' unconfirmed absence notices
— so «تثبيت حضور اليوم» has something to confirm and to simulate —, the demo student and parent), guarded by
`dedupe_key`. All dates come from the `demo_days` helper table the seed creates and drops (`rn 1` = demo day).

## Deployment (integrator, §9)

```bash
cd madar/app/client && npm ci && npm run build          # → client/dist
cd ../server && npm ci
npx wrangler secret put TOKEN_SECRET                     # any long random string (required: login fails without it)
npx wrangler secret put ADMIN_KEY                        # unlocks /api/admin/* (schema, seed, reseed, health)
npx wrangler deploy                                      # then attach the custom domain app.madar.raqeem.dev
ADMIN_KEY=… curl -X POST -H "x-admin-key: $ADMIN_KEY" https://app.madar.raqeem.dev/api/admin/reseed   # first fill (or scripts/apply-sql.mjs)
```

`[vars]`: `WEEKLY_CAP`, `APP_URL`, `SUPPORT_PHONE` (empty until the team has a line), `SUPPORT_HOURS` («٧:٣٠–١٤:٠٠»).
The cron `0 3 * * *` (06:00 Damascus) runs `reseed()`: drop every table, schema, seed, then the warm-up
(`directorateOverview(reportDate())`: the engine fills the pending periods and notifies the school accounts; the day's
alerts become the directorate's notifications).

## Notes and deviations from the spec

- `schema.sql` uses `CREATE TABLE IF NOT EXISTS` (re-runnable) and adds `homework.client_id TEXT UNIQUE`,
  `schools.principal/phone` and `notifications.dedupe_key` (unique index; NULLs stay distinct).
- Substitute suggestions for the seeded absences are created lazily by `ensureSubstitutions` (or by the reseed warm-up)
  instead of being hard-coded in SQL, so they always match the current weekday; the decided ones are seeded in SQL.
- Extra, documented endpoints: `GET /api/config`, `GET /api/announcements`, `GET /api/sections/:id/roster`,
  `GET /api/school/teachers`, `GET /api/directorate/school/:id`, `GET /api/directorate/report`, `?week=` on the CSV;
  `?date=` on the home/dashboard routes; `user.demo = true` for the pilot's seeded accounts.
- The engine notification reads «… بحاجة إلى تغطية» (number-agnostic) and counts the periods it had to open.
- `npm install` needs `legacy-peer-deps` (set in `.npmrc`): wrangler 4.157 declares an optional peer on
  `@cloudflare/workers-types@^5` that npm 10 otherwise fails to resolve.
