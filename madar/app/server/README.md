# مَدار — الخادم (Cloudflare Worker + D1)

خادم منصّة «مَدار» التجريبية لمديرية تربية درعا: واجهة برمجية تحت `/api/*` (Hono + D1)، ويقدّم واجهة التطبيق المبنيّة من
`../client/dist` كملفّات ثابتة. المواصفة الكاملة في `madar/docs/mvp-spec.md`.

## التشغيل محليًا (باختصار)

```bash
npm install            # يستخدم legacy-peer-deps تلقائيًا (.npmrc)
npm run db:apply       # ينشئ قاعدة D1 المحلّية ويطبّق schema.sql ثم seed.sql (بيانات اليوم)
npm run dev            # http://localhost:8787 — يحتاج ../client/dist (ابنِ العميل أولًا)
npm run dev:api        # الواجهة البرمجية فقط من دون العميل (ملفّات ثابتة بديلة)
npm test               # اختبارات vitest (المحرّك، الرموز، المسارات على SQLite في الذاكرة)
npm run smoke          # اختبار دخان كامل على wrangler dev --local
```

على يوم جديد أعد تهيئة البيانات التجريبية: `npm run db:reset` (التواريخ في seed.sql نسبية إلى تاريخ اليوم بتوقيت دمشق).
اقتراحات التعويض لغياب أ. رنا سعيد «اليوم» ينتجها المحرّك نفسه عند أول فتح للوحة المدرسة (أو صفحة المعلّم)، فتطابق يوم
الأسبوع الحالي دائمًا. يومَي الجمعة والسبت لا حصص، فتظهر الصفحات فارغة؛ للعرض أضف `?date=YYYY-MM-DD` إلى مسارات الصفحة الرئيسية.

# Madar server — English reference

Cloudflare Worker (TypeScript, Hono) with a D1 database. API under `/api/*`; every other path is served from the
built client (`[assets]` binding, `run_worker_first = true`) with an SPA fallback to `index.html` for paths without a
file extension. Spec: `madar/docs/mvp-spec.md` (§3–6, §8, §9, §11 are implemented here).

## Layout

```
package.json  wrangler.toml (§9, database_id = "REPLACE_ME")  wrangler.local.toml (API-only dev: stub assets)
schema.sql    seed.sql (generated by scripts/gen-seed.mjs — edit the generator, not the SQL)
src/index.ts        Hono app, CORS, error → {error: "<Arabic>"}, assets fallback
src/auth.ts         HMAC-SHA256 tokens (Web Crypto), login rate limit, requireAuth(...roles)
src/scope.ts        who may see which section / student / teacher
src/substitute.ts   §6 engine: pure rankCandidates/suggest + runEngine/ensureSubstitutions (D1)
src/notify.ts       notification fan-out + console.log('[SMS]', phone, body) stub
src/stats.ts        dashboard numbers (day status per student, per-school stats, three-day absences)
src/csv.ts          UTF-8 BOM CSV
src/routes/{common,teacher,student,parent,school,directorate}.ts
test/               vitest: substitute.test.ts, auth.test.ts, routes.test.ts (+ d1.ts: D1 shim over node:sqlite)
scripts/smoke.sh    end-to-end smoke against wrangler dev --local (port 8787)
```

## Local development

```bash
npm install                 # .npmrc sets legacy-peer-deps (wrangler 4 ↔ @cloudflare/workers-types peer range)
npm run db:apply            # local D1: schema.sql + seed.sql   (= npx wrangler d1 execute madar --local --file=…)
npm run dev                 # wrangler dev --local on :8787, serves ../client/dist  (build the client first)
npm run dev:api             # same Worker with a stub assets folder (scripts/assets-stub) — no client build needed
npm test                    # vitest, no network, no workerd (routes run against schema+seed in an in-memory SQLite)
npm run typecheck           # tsc --noEmit
npm run smoke               # scripts/smoke.sh: fresh local D1, logs in as every role, GETs + one POST per role
npm run db:reset            # wipe .wrangler/state and re-apply (do this on a new day: seed dates are relative to today)
npm run seed:gen            # regenerate seed.sql from scripts/gen-seed.mjs
```

Both wrangler configs use the same `database_id`, so `db:apply` feeds `dev` and `dev:api` alike. `TOKEN_SECRET`
defaults to `dev-secret` when unset (put a real one in `.dev.vars` locally or `wrangler secret put` in production).
The Vite dev server of the client proxies `/api` to `http://localhost:8787`.

## Authentication (§4)

`POST /api/login {code}` → `{token, user, context}`. Token = `base64url(JSON {uid, role, exp}) + "." + base64url(HMAC-SHA256)`,
`exp` in unix seconds, 30 days. Send `Authorization: Bearer <token>`. Only the CSV report additionally accepts
`?token=` (a download link cannot carry a header). Login is limited to 20 attempts per IP per 10 minutes (in-memory).
Every route checks role and scope; every write is recorded in `audit_log (user_id, action, target)`. Phone numbers are
never returned by any endpoint.

Notification `kind`s: `homework`, `absence` (guardian; `sms` flips to 1 on confirmation), `absence_teacher` (school
account, from the engine), `substitution` (the substitute, with the lesson note), `change` (students + guardians,
«تغيّر معلّم الحصّة الثالثة اليوم», or the self-study note), `announcement` (also directorate circulars), `message`.
`link` values: `/homework/:id`, `/attendance?date=YYYY-MM-DD&student_id=N`, `/absences/:id`, `/substitutions/:id`,
`/timetable?date=…`, `/announcements/:id`, `/messages/:user_id` — hints for the client; the client owns its routes.

Dates are `YYYY-MM-DD` in Damascus time; day 0 = الأحد … 4 = الخميس. "Day status" of a student = status of the first
recorded period of that day (`present`/`late` count as present). Alerts: `no_attendance` (school day, nothing uploaded),
`uncovered` (suggested rows not yet approved / self-study), `three_days` (absent on three or more consecutive school
days, counting back from the report date; days with no upload at all are skipped).

## Substitute engine (§6)

`src/substitute.ts`: `rankCandidates(slot, ctx)` / `suggest(slots, ctx)` are pure. Eligible = same school, free at that
day/period, not absent that date, not already assigned at that period, and `weekly periods + substitutions this week <
WEEKLY_CAP` (env, default 28). Tier 1 same subject, tier 2 teaches the section, tier 3 others; within a tier fewer
approved substitutions this month, then fewer weekly periods, then name. The top 3 are stored as `candidates`
(`[{teacher_id,name,subject,tier,reason}]`), the first as `substitute_teacher_id`, status `suggested`; with nobody free
`candidates=[]` and `no_candidate=true`. The school account is notified «غياب أ. … اليوم: N حصص بحاجة إلى تغطية».
`runEngine` is idempotent (`INSERT OR IGNORE`); `ensureSubstitutions(date)` runs it for absences that have no rows yet
(this is how the seeded absence gets its suggestions on the first dashboard load).

## Seed (§8) — `seed.sql`, idempotent, generated

Three schools (school 1 full: 7 teachers, 3 sections × 12 students, 8 guardians per section; schools 2–3 minimal),
Sun–Thu timetable with the pitch's anchors (الخامس (ب) Thursday = عربي، رياضيات، علوم، إنكليزي، دراسات، رياضة; سامر free in
period 5, ماهر free in period 3), homework «تمارين الكسور العشرية ص ٤٢» due in 3 days, attendance for the last five
school days (~94 % present, today's periods 1–2 only, earlier days confirmed), يزن عماد absent three consecutive school
days, school 3 without today's upload, رنا سعيد absent today, one school announcement and one circular. All dates use
`date('now','+3 hours')` (Damascus = UTC+3), so apply the seed on the demo day or run `npm run db:reset`.

## Deployment (integrator, §9)

```bash
cd madar/app/client && npm ci && npm run build          # → client/dist
cd ../server && npm ci
npx wrangler d1 create madar                             # paste the id into wrangler.toml (database_id = "REPLACE_ME")
npx wrangler d1 execute madar --remote --file=schema.sql
npx wrangler d1 execute madar --remote --file=seed.sql
npx wrangler secret put TOKEN_SECRET                     # any long random string
npx wrangler deploy                                      # then attach the custom domain app.madar.raqeem.dev
```

## Notes and deviations from the spec

- `schema.sql` uses `CREATE TABLE IF NOT EXISTS` (re-runnable) and adds `homework.client_id TEXT UNIQUE`.
- The seeded absence's suggestions are created lazily by `ensureSubstitutions` on the first dashboard / home load
  instead of being hard-coded in SQL, so they always match the current weekday (`POST /api/absences` also works).
- Extra, documented endpoints: `GET /api/announcements`, `GET /api/sections/:id/roster`, `GET /api/school/teachers`;
  `?date=` on the home/dashboard routes; `?token=` on the CSV route; `user.demo = true` for the pilot's seeded accounts.
- The engine notification reads «… بحاجة إلى تغطية» (number-agnostic) rather than «تحتاج تغطية».
- The engine ranks tier-2 candidates by load, so for رنا's Thursday period 5 it proposes عمر سعد (12 periods) before
  سامر حسن (18) — the pitch mock-up shows سامر; the spec's rule wins.
- `npm install` needs `legacy-peer-deps` (set in `.npmrc`): wrangler 4.157 declares an optional peer on
  `@cloudflare/workers-types@^5` that npm 10 otherwise fails to resolve.
