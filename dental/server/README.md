# موقع Dentora ولوحة التحكم (Cloudflare Worker باسم dentora-api)

كل ما هو على الإنترنت من Dentora يعمل من مكان واحد: Worker على Cloudflare اسمه `dentora-api`، على العنوان
**https://dentora.raqeem.dev**. لا يحتاج خادماً ولا استضافة أخرى.

## ماذا يوجد على الموقع

| العنوان | ما هو |
|---|---|
| `/` و`/en` | صفحة الهبوط بالعربية والإنجليزية: المزايا، صور البرنامج، السعر، التحميل، الأسئلة الشائعة. السعر ورقم واتساب وشريط الإعلان تُعدَّل من لوحة التحكم |
| `/admin` | **لوحة التحكم** (لك وحدك، بكلمة مرور): إصدار أكواد التفعيل، رموز إعادة تعيين PIN، سجل التراخيص والزبائن، التحقق من أي كود، الإعدادات، سجل النشاط، وأرقام المبيعات والتنزيلات |
| `/download/android` | تنزيل ملف APK للإصدار الحالي (يُحتسب التنزيل في اللوحة) |
| `/download/windows` | يذهب إلى رابط مثبّت ويندوز الذي تضعه في الإعدادات، وإن لم تضعه يفتح واتساب برسالة تطلب منك نسخة ويندوز |
| `/privacy`، `/terms` (و`/en/privacy`، `/en/terms`) | سياسة الخصوصية وشروط الاستخدام، النصوص نفسها الموجودة داخل التطبيق |

التفاصيل التقنية الكاملة (المسارات وقواعد الأمان) في `SPEC.md`، للمبرمج.

| الدومين (Production) | https://dentora.raqeem.dev |
| رابط workers.dev | https://dentora-api.almutafawiqin.workers.dev |
| Account ID | `c79a8e91efac74d2e119e7e406c4db43` |
| Zone | `raqeem.dev` |
| Zone ID | `f6580fdc4936cc1d394eac2d06c4f4d1` |
| قاعدة البيانات | D1 باسم `dentora` (تُنشأ تلقائياً في أول نشر، والجداول ينشئها الـ Worker بنفسه) |

- **اسم الـ Worker** في `wrangler.toml` يجب أن يبقى `dentora-api` حتى يُنشر على الـ Worker نفسه لا على Worker جديد.
- **الدومين** مربوط كـ Custom Domain، فلا يحتاج الإعداد Zone ID؛ مذكور هنا للرجوع إليه فقط.
- Account ID وZone ID معرّفات وليست أسراراً، فلا بأس بوجودها في المستودع.

## الإعداد لأول مرة (خطوة بخطوة)

تحتاج جهازاً عليه Node.js 22 ونسخة من المستودع. كل الأوامر تُكتب في الطرفية (Terminal).

**1. أنشئ مفتاح النشر (API Token) من Cloudflare**

1. ادخل إلى https://dash.cloudflare.com/profile/api-tokens واضغط **Create Token**.
2. اختر القالب **Edit Cloudflare Workers** واضغط **Use template**.
3. في **Permissions** اضغط **+ Add more** وأضف: **Account** ← **D1** ← **Edit** (لإنشاء قاعدة البيانات).
4. في **Account Resources** اختر حساب Dentora، وفي **Zone Resources** اختر **Specific zone** ← `raqeem.dev`.
5. اضغط **Continue to summary** ثم **Create Token**، وانسخ المفتاح (يظهر مرة واحدة فقط) واحفظه في مكان آمن.

ثم ضعه في الطرفية قبل الأوامر التالية (لا تكتبه في أي ملف داخل المستودع):

```bash
export CLOUDFLARE_API_TOKEN=<المفتاح الذي نسخته>
```

**2. ثبّت الأدوات**

```bash
cd dental/server
npm install
```

**3. اضبط كلمة مرور لوحة التحكم**

```bash
npx wrangler secret put ADMIN_PASSWORD
```

يطلب الأمر كلمة المرور ولا يعرضها. اختر كلمة مرور قوية من **12 حرفاً على الأقل** (وإلا لن تفتح اللوحة وستعرض لك
طريقة ضبطها)، ولا تستعملها في أي موقع آخر.

**4. ارفع مفتاح التوقيع الخاص (لإصدار الأكواد)**

```bash
npx wrangler secret put LICENSE_PRIVATE_JWK < ../../secrets-for-user/dentora/license-private.jwk
```

هذا هو المفتاح الذي يوقّع أكواد التفعيل. بدونه تفتح اللوحة لكنها لا تصدر أكواداً (وتعرض تنبيهاً بذلك).

**5. انشر**

```bash
npm run deploy
```

في أول مرة ينشئ هذا الأمر قاعدة البيانات `dentora` تلقائياً، ويرفع الموقع ولوحة التحكم وملف APK الإصدار الحالي.

**6. جرّب**

- افتح https://dentora.raqeem.dev وتأكد أن الصفحة تظهر وأن زر أندرويد ينزّل الملف.
- افتح https://dentora.raqeem.dev/admin وادخل بكلمة المرور، ثم اذهب إلى **الإعدادات**: تأكد أن «توقيع الرموز» جاهز،
  وراجع السعر ورقم واتساب.
- (اختياري) https://dentora.raqeem.dev/healthz يعيد `ok`.

## نشر إصدار جديد من التطبيق (APK)

1. ابنِ ملف APK الجديد للتطبيق كالمعتاد (برقم الإصدار الجديد في `dental/package.json`).
2. ضع الملف في `dental/releases/` باسم `Dentora-<الإصدار>.apk` (مثل `Dentora-1.0.1.apk`)، واحذف القديم إن أردت.
3. انشر من جديد:

```bash
cd dental/server
npm run deploy
```

تعرض الصفحة رقم الإصدار وحجم الملف الجديدين تلقائياً، ويحمل الملف المنزَّل اسم `Dentora-<الإصدار>.apk`.

## رابط تنزيل ويندوز

ملف تثبيت ويندوز أكبر من أن يُرفع على الـ Worker، فارفعه على أي مكان يعطي رابط تنزيل مباشراً يبدأ بـ `https://`
(مثل GitHub Releases أو Google Drive أو Cloudflare R2)، ثم في لوحة التحكم: **الإعدادات** ← **التنزيلات** ←
**رابط تنزيل ويندوز**، الصق الرابط واحفظ. يتغير زر ويندوز في الموقع خلال 30 ثانية من «اطلب نسخة ويندوز» إلى
«حمّل لويندوز». إن تركت الحقل فارغاً، يفتح الزر واتساب برسالة يطلب فيها الزبون النسخة منك.

## ملاحظات أمان

- **كلمة المرور:** قوية، 12 حرفاً أو أكثر، ولا تُستعمل في مكان آخر. **تغييرها يُخرج كل الجلسات المفتوحة** على كل
  الأجهزة (نفّذ الأمر في الخطوة 3 بكلمة جديدة؛ لا حاجة لنشر جديد). الجلسة تدوم 12 ساعة، و«تسجيل الخروج» ينهيها فوراً
  حتى لو نُسخت.
- **المفتاح الخاص** يعيش فقط كسر في Cloudflare (`LICENSE_PRIVATE_JWK`): لا يُوضع في المستودع ولا في أي ملف يُرفع، ولا
  تعيده اللوحة ولا يُكتب في أي سجل. من يملكه يستطيع إصدار أكواد تفعيل، فاحتفظ بالملف الأصلي في مكان آمن خارج الإنترنت.
- **محاولات الدخول:** بعد 5 محاولات خاطئة من العنوان نفسه يتوقف الدخول منه 15 دقيقة. وإن جاءت 30 محاولة خاطئة من
  عناوين مختلفة يتوقف الدخول مؤقتاً من **المتصفحات الجديدة** فقط؛ أما المتصفح الذي دخلت منه سابقاً فيبقى يعمل، فادخل من
  جهازك المعتاد. كل محاولة دخول تُسجَّل في «سجل النشاط».
- **مفتاح النشر (API Token)** يبقى على جهازك فقط. إن ظننت أنه تسرّب، احذفه من صفحة API Tokens وأنشئ غيره.
- التنزيلات تُحتسب مرة واحدة لكل زائر في اليوم، فالأرقام في اللوحة لا تتضخم بإعادة التحميل.

## للمبرمج: الأسرار والتشغيل المحلي

| السر | أين | ما هو |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | بيئة جهاز النشر | مفتاح النشر (قالب **Edit Cloudflare Workers** + Account ← D1 ← Edit، الحساب حساب Dentora، وZone `raqeem.dev`) |
| `ADMIN_PASSWORD` | سر في الـ Worker | كلمة مرور لوحة التحكم، 12 حرفاً على الأقل |
| `LICENSE_PRIVATE_JWK` | سر في الـ Worker | JSON المفتاح الخاص من `secrets-for-user/dentora/license-private.jwk` |

انسخ `.dev.vars.example` إلى `.dev.vars` (لا يُحفظ في المستودع) واملأ القيمتين (المفتاح سطر JSON واحد بين علامتي
اقتباس مفردتين)، ثم:

```bash
npm run dev       # http://localhost:8787 ، قاعدة D1 محلية
npm run check     # بناء public/ + فحص الأنواع + wrangler deploy --dry-run (بدون مفتاح)
npm test          # اختبارات الوحدات (vitest)
npm run e2e       # اختبار شامل: يشغّل wrangler dev على قاعدة فارغة ويفحص الصفحات والتحميلات وكل مسارات API ولوحة التحكم في Chromium
```

`npm run build` (ويستدعيه `deploy` و`check` و`dev`) يجمع `public/` من `site/` ومن ملف APK الإصدار الحالي في
`../releases/Dentora-<version>.apk`. `public/` لا يُحفظ في المستودع.

`npm run e2e` يستعمل Playwright من `node_modules` التطبيق (`dental/`)، ويحتاج المنافذ 8831 إلى 8833 (يغيّرها
`E2E_PORT`). الصور واللقطات وسجلات الـ Worker تُكتب في `.wrangler/e2e/` (يغيّرها `E2E_OUT`)، ويطبع سطراً لكل فحص
وينتهي برمز خطأ إن فشل أي فحص.
