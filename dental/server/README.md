# موقع Dentora ولوحة التحكم (Cloudflare Worker باسم dentora-api)

كل ما هو على الإنترنت من Dentora يعمل من مكان واحد: Worker على Cloudflare اسمه `dentora-api`، على العنوان
**https://dentora.raqeem.dev**. لا يحتاج خادماً ولا استضافة أخرى.

## ماذا يوجد على الموقع

| العنوان | ما هو |
|---|---|
| `/` و`/en` | صفحة الهبوط بالعربية والإنجليزية: المزايا، صور البرنامج، السعر، التحميل، الأسئلة الشائعة. السعر ورقم واتساب وشريط الإعلان تُعدَّل من لوحة التحكم |
| `/admin` | **لوحة التحكم** (لك وحدك، بكلمة مرور): إصدار أكواد التفعيل ومفاتيح الترخيص، رموز إعادة تعيين PIN، سجل التراخيص والزبائن، التحقق من أي كود أو مفتاح، الإعدادات، سجل النشاط، وأرقام المبيعات والتنزيلات |
| `/activate` و`/en/activate` | **صفحة التفعيل** العامة: يكتب فيها الزبون رقم جهازه ومفتاح الترخيص، فيحصل على كود التفعيل لجهازه ليلصقه في البرنامج. تعمل مع كل إصدارات التطبيق (ومنها 1.0.0) ومن أي جهاز متصل بالإنترنت، والرابط `/activate?device=XXXX-XXXX` يكتب رقم الجهاز فيها مسبقاً. انظر «البيع بمفاتيح الترخيص» |
| `/download/android` | تنزيل ملف APK للإصدار الحالي (يُحتسب التنزيل في اللوحة) |
| `/download/windows` | تنزيل مثبّت ويندوز `Dentora-Setup-<الإصدار>.exe` إن نشرته مع الموقع (يُحتسب التنزيل في اللوحة). وإن لم يُنشر، يذهب إلى رابط ويندوز الذي تضعه في الإعدادات، وإن لم تضعه يفتح واتساب برسالة تطلب منك نسخة ويندوز. انظر «مثبّت ويندوز على الموقع» |
| `/privacy`، `/terms` (و`/en/privacy`، `/en/terms`) | سياسة الخصوصية وشروط الاستخدام، النصوص نفسها الموجودة داخل التطبيق |

التفاصيل التقنية الكاملة (المسارات وقواعد الأمان) في `SPEC.md`، للمبرمج.

- **اسم الـ Worker** في `wrangler.toml` يجب أن يبقى `dentora-api` حتى يُنشر على الـ Worker نفسه لا على Worker جديد.
- **الدومين** مربوط كـ Custom Domain، فلا يحتاج الإعداد Zone ID؛ مذكور هنا للرجوع إليه فقط.
- Account ID وZone ID معرّفات وليست أسراراً، فلا بأس بوجودها في المستودع.

## الإعداد لأول مرة (خطوة بخطوة)

تحتاج جهازاً عليه Node.js 22 ونسخة من المستودع. كل الأوامر تُكتب في الطرفية (Terminal).

**1. أنشئ مفتاح النشر (API Token) من Cloudflare**

1. ادخل إلى https://dash.cloudflare.com/profile/api-tokens واضغط **Create Token**.
2. اختر القالب **Edit Cloudflare Workers** واضغط **Use template**.
3. في **Permissions** اضغط **+ Add more** وأضف: **Account** ← **D1** ← **Edit** (لإنشاء قاعدة البيانات).
4. في **Account Resources** اختر حساب Dentora، وفي **Zone Resources** اختر **Specific zone** ← `raqeem.dev`.
5. اضغط **Continue to summary** ثم **Create Token**، وانسخ المفتاح (يظهر مرة واحدة فقط) واحفظه في مكان آمن.

ثم ضعه في الطرفية قبل الأوامر التالية (لا تكتبه في أي ملف داخل المستودع):

```bash
export CLOUDFLARE_API_TOKEN=<المفتاح الذي نسخته>
```

**2. ثبّت الأدوات**

```bash
cd dental/server
npm install
```

**3. اضبط كلمة مرور لوحة التحكم**

```bash
npx wrangler secret put ADMIN_PASSWORD
```

يطلب الأمر كلمة المرور ولا يعرضها. اختر كلمة مرور قوية من **12 حرفاً على الأقل** (وإلا لن تفتح اللوحة وستعرض لك
طريقة ضبطها)، ولا تستعملها في أي موقع آخر.

**4. ارفع مفتاح التوقيع الخاص (لإصدار الأكواد وتفعيل المفاتيح)**

```bash
npx wrangler secret put LICENSE_PRIVATE_JWK < ../../secrets-for-user/dentora/license-private.jwk
```

هذا هو المفتاح الذي يوقّع أكواد التفعيل، سواء أصدرتها من اللوحة أو صنعها الموقع من مفتاح ترخيص. بدونه تفتح اللوحة لكنها
لا تصدر أكواداً، ولا يستطيع الزبائن تفعيل مفاتيحهم (وتعرض اللوحة تنبيهاً بذلك).

**5. انشر**

```bash
npm run deploy
```

في أول مرة ينشئ هذا الأمر قاعدة البيانات `dentora` تلقائياً، ويرفع الموقع ولوحة التحكم وملف APK الإصدار الحالي، ومثبّت
ويندوز إن وضعته (انظر «مثبّت ويندوز على الموقع»).

**6. جرّب**

- افتح https://dentora.raqeem.dev وتأكد أن الصفحة تظهر وأن زر أندرويد ينزّل الملف، وزر ويندوز المثبّت إن نشرته.
- افتح https://dentora.raqeem.dev/admin وادخل بكلمة المرور، ثم اذهب إلى **الإعدادات**: تأكد أن «توقيع الرموز» جاهز،
  وراجع السعر ورقم واتساب.
- افتح https://dentora.raqeem.dev/activate وتأكد أن صفحة التفعيل تظهر.
- (اختياري) https://dentora.raqeem.dev/healthz يعيد `ok`.

## نشر إصدار جديد من التطبيق (APK)

1. ابنِ ملف APK الجديد للتطبيق كالمعتاد (برقم الإصدار الجديد في `dental/package.json`).
2. ضع الملف في `dental/releases/` باسم `Dentora-<الإصدار>.apk` (مثل `Dentora-1.0.1.apk`)، واحذف القديم إن أردت.
3. انشر من جديد:

```bash
cd dental/server
npm run deploy
```

تعرض الصفحة رقم الإصدار وحجم الملف الجديدين تلقائياً، ويحمل الملف المنزَّل اسم `Dentora-<الإصدار>.apk`. ولتنشر معه
مثبّت ويندوز الجديد، انظر القسم التالي.

## مثبّت ويندوز على الموقع

مثبّت ويندوز (نحو 100 ميغابايت) أكبر من الحد الأقصى لملف واحد على الـ Worker (25 ميغابايت)، فيقسّمه `npm run build`
إلى أجزاء من 20 ميغابايت، ويرسلها الموقع متتالية ملفاً واحداً عند الضغط على «تحميل لويندوز»، فيصل إلى الزبون
`Dentora-Setup-<الإصدار>.exe` كاملاً. الملف أكبر من أن يُحفظ في git، فلا يوجد في المستودع؛ ضعه قبل النشر في
`dental/releases/Dentora-Setup-<الإصدار>.exe` (الإصدار نفسه الذي في `dental/package.json`)، أو أعطِ مكانه عند النشر:

```bash
WINDOWS_SETUP=/المسار/إلى/Dentora-Setup-1.0.0.exe npm run deploy
```

يعرض الموقع عندها رقم الإصدار وحجم الملف وتنبيهاً بشاشة «حماية Windows» التي قد تظهر لأن البرنامج غير موقّع
بشهادة بعد. إن لم يكن المثبّت موجوداً عند النشر، يذهب زر ويندوز إلى الرابط الذي تضعه في لوحة التحكم:
**الإعدادات** ← **التنزيلات** ← **رابط تنزيل ويندوز** (رابط مباشر يبدأ بـ `https://`، مثل GitHub Releases أو Google
Drive)، وإن تركته فارغاً يفتح الزر واتساب برسالة يطلب فيها الزبون النسخة منك.

**الملفات الكبيرة التي لا يحفظها git:** مثبّت ويندوز وفيديوهات الدورة التعليمية (`site/videos/`) ليست في المستودع،
و`wrangler deploy` ينشر ما في `public/` بالضبط: لو نشرت من جهاز ليست عليه لاختفت من الموقع. لذلك يبدأ `npm run deploy`
بتشغيل `scripts/fetch-published.mjs`، الذي يقرأ الموقع الحي ويحمّل ما ينقص هذا الجهاز منها إلى مكانه (المثبّت إلى
`dental/releases/`، والفيديوهات إلى `site/videos/`) ويتحقق من حجمه (ومن بصمته SHA-256 حين يعلنها الموقع)، ولا يستبدل
ملفاً موجوداً أبداً؛ يطبع سطراً لكل ملف (fetched / present / skipped وسببه)، ويتوقف قبل النشر إن فشل التحقق أو تعذّر
تحميل ملف يعلنه الموقع. لتشغيله وحده: `npm run fetch-published`؛ وللنشر بما على هذا الجهاز فقط (فيُحذف من الموقع ما
ينقصه): `SKIP_FETCH=1 npm run deploy`.

## البيع بمفاتيح الترخيص

كل كود تفعيل موقَّع لجهاز واحد، لذلك يحتاج إصداره إلى رقم جهاز الزبون. **مفتاح الترخيص** يعفيك من ذلك: تصدره من اللوحة دون
رقم الجهاز، ويحوّله الزبون بنفسه إلى كود التفعيل المعتاد لجهازه، مرة واحدة وعبر الإنترنت. المفتاح 16 خانة بالشكل
`XXXX-XXXX-XXXX-XXXX`، من حروف وأرقام ليس فيها 0 ولا O ولا 1 ولا I. التفاصيل التقنية في `../docs/LICENCE-KEYS.md`.

**مفتاح أم كود لرقم الجهاز؟** الطريقتان في صفحة **ترخيص جديد**، وإصدار الكود برقم الجهاز باقٍ كما كان.

| الحالة | الأنسب |
|---|---|
| تبيع قبل أن يثبّت الزبون البرنامج، أو لا تريد انتظار رقم جهازه | مفتاح |
| تبيع لموزّع يعيد البيع لعيادات لا تعرفها | دفعة مفاتيح |
| أرسل إليك الزبون رقم جهازه | كود لرقم الجهاز: يصله جاهزاً ولا يحتاج إلى إنترنت |
| لا يتصل أي جهاز لدى العيادة بالإنترنت | كود لرقم الجهاز |

**إصدار مفتاح أو دفعة مفاتيح**

1. في اللوحة اضغط **ترخيص جديد**، واختر في «طريقة البيع» **مفتاح ترخيص**.
2. اختر الباقة والمدة: **مدى الحياة**؛ أو **سنة** أو **سنتان** تبدآن من يوم تفعيل المفتاح لا من يوم البيع؛ أو **حتى تاريخ**:
   يعمل الكود حتى ذلك اليوم، ولا يُقبل تفعيل المفتاح بعده.
3. في **عدد المفاتيح** اترك 1، أو اكتب عدداً حتى 50 لموزّع. مفاتيح الدفعة كلها بالباقة والمدة وبيانات البيع نفسها، و«المبلغ
   المدفوع» يُسجَّل لكل مفتاح على حدة (الافتراضي السعر الذي في الإعدادات).
4. اكتب بيانات الزبون واضغط **إصدار المفتاح** (أو «إصدار 3 مفاتيح» مثلاً). لا يلزم رقم الجهاز.

تظهر المفاتيح ومعها رسالة جاهزة، بالعربية أو بالإنجليزية، فيها المفتاح والباقة والمدة وطريقتا التفعيل، فأرسلها بزر **إرسال على
واتساب** إلى رقم الزبون الذي كتبته. في الدفعة ينسخ زر **نسخ الكل** المفاتيح مفتاحاً في كل سطر لتعطيها للموزّع، وتختار من
«رسالة أي مفتاح؟» رسالة كل مفتاح على حدة.

يُحتسب المفتاح بيعاً من يوم إصداره (في عدد التراخيص والإيرادات)، ويظهر في **التراخيص** مع بقية المبيعات بحالة «بانتظار
التفعيل»، فإذا فُعّل ظهر معه رقم الجهاز الذي فُعّل عليه، وفي تفاصيله تاريخ التفعيل. ابحث بالمفتاح (بالشرطات أو دونها)، أو
اختر «بانتظار التفعيل» من قائمة الحالة. وتعرض **الرئيسية** عدد المفاتيح التي لم تُفعَّل بعد، ويعرض **التحقق من رمز أو مفتاح**
حالة أي مفتاح تلصقه، وعلى أي جهاز فُعّل ومتى. وفي ملف CSV أعمدة المفتاح والمدة وتاريخ التفعيل.

**ما يفعله الزبون** (مرة واحدة)

- **في البرنامج (الإصدار 1.1.0 فما بعده):** الإعدادات ← الترخيص، يلصق المفتاح (أو الرسالة كاملة) في حقل الكود نفسه ويضغط
  «تفعيل» والجهاز متصل بالإنترنت. يرسل البرنامج المفتاح ورقم الجهاز فقط إلى `https://dentora.raqeem.dev/api/activate`، فيعود
  كود التفعيل الموقَّع لهذا الجهاز، ويتحقق منه البرنامج بمفتاحه العام كأي كود ترسله أنت، ثم يعمل دون إنترنت.
- **من صفحة التفعيل:** https://dentora.raqeem.dev/activate (وبالإنجليزية `/en/activate`) من أي جهاز متصل بالإنترنت، ولو كان
  هاتفاً: يكتب رقم جهازه (يجده في الإعدادات ← الترخيص) والمفتاح، فيظهر له كود التفعيل ليلصقه في البرنامج. هذه هي الطريقة مع
  **الإصدار 1.0.0**، الذي لا يقبل المفتاح نفسه لكنه يقبل الكود الذي تعطيه الصفحة، ومع جهاز عيادة لا يصل إلى الإنترنت. وإن
  تعذّر على البرنامج الوصول إلى الخادم يعرض زر «التفعيل من المتصفح»، فتُفتح الصفحة ورقم الجهاز مكتوب فيها (إلا في نسخة
  Google Play، التي لا تعرض أي رابط إلى الموقع).

**قواعد المفاتيح**

- **مفتاح واحد لجهاز واحد.** يرتبط المفتاح بأول جهاز يفعّله. إن أدخله الجهاز نفسه مرة أخرى (بعد إعادة تثبيت البرنامج أو حذف
  بياناته) يعود إليه الكود نفسه، ويُرفض على أي جهاز آخر. لعيادة فيها ثلاثة أجهزة بِع ثلاثة مفاتيح.
- **إن غيّر الزبون جهازه** (جهاز جديد، أو ويندوز أو هاتف أُعيد ضبطه، فيتغيّر رقم الجهاز) فلن يعمل المفتاح القديم على الجهاز
  الجديد: أصدر له مفتاحاً جديداً، أو كوداً لرقم جهازه الجديد، وذكّره بأن يأخذ نسخة احتياطية من الجهاز القديم ويستعيدها على
  الجديد. وتحويل المفتاح القديم إلى «ملغى» أو «مسترد» بعد تفعيله لا يوقف الجهاز القديم: كوده يعمل دون إنترنت ولا يمكن سحبه،
  كأي كود أصدرته برقم الجهاز، والحالة عندها لسجلاتك وأرقامك فقط.
- **الاسترداد قبل التفعيل:** افتح المفتاح في **التراخيص** وغيّر حالته إلى **مسترد** (أو **ملغى** لمفتاح صدر خطأً)، فيُرفض
  تفعيله على أي جهاز. وإن أعدته إلى **فعّال** أمكن تفعيله من جديد.
- **التجديد:** حين تنتهي مدة مفتاح السنة أو السنتين، بِع الزبون مفتاحاً جديداً يفعّله على الجهاز نفسه، أو كوداً لرقم جهازه.
- **المفتاح قبل تفعيله كالنقد:** من يملكه يستطيع تفعيله على جهازه، فأرسله إلى صاحبه وحده. وإن ظننت أن مفتاحاً لم يُفعَّل بعد وصل
  إلى غير صاحبه، فألغِه وأصدر غيره.
- **حدّ المحاولات:** إذا فشلت 10 محاولات تفعيل من عنوان الإنترنت نفسه خلال 15 دقيقة (مفتاح خاطئ أو غير موجود، أو مستعمل على
  جهاز آخر، أو ملغى أو انقضى يومه، أو رقم جهاز غير صالح)، يُرفض التفعيل من ذلك العنوان حتى تمضي 15 دقيقة على أقدم تلك
  المحاولات، ويرى الزبون كم ينتظر. التفعيل الناجح لا يُحتسب. هذا الحد يمنع تخمين المفاتيح، ولن يبلغه زبون يلصق مفتاحه الصحيح.
- **سجل النشاط** يسجّل كل تفعيل («تفعيل مفتاح ترخيص» مع آخر 4 خانات من المفتاح ورقم الجهاز)، وكل محاولة لتفعيل مفتاح مستعمل
  على جهاز آخر، فتعرف إن كان أحد يتداول مفتاحاً. ولا يُكتب المفتاح كاملاً في السجل أبداً.
- **المفاتيح تحتاج مفتاح التوقيع:** الكود يُوقَّع لحظة التفعيل بالسر `LICENSE_PRIVATE_JWK` (الخطوة 4). تستطيع إصدار المفاتيح
  وهو غير مضبوط (وتنبّهك اللوحة إلى ذلك)، لكن لن يُفعَّل أي مفتاح حتى تضبطه، فتأكد في **الإعدادات** أن «توقيع الرموز» جاهز قبل
  أن تبيع مفاتيح.

**ما الذي يصل إلى الخادم:** المفتاح ورقم الجهاز فقط، مرة واحدة، ولا شيء من بيانات العيادة أو المرضى. يحفظ الخادم رقم الجهاز
ووقت التفعيل مع سجل البيع ليرفض المفتاح على جهاز آخر، ويَعُدّ المحاولات الفاشلة من كل عنوان مدة 15 دقيقة فقط. وهذا ما تنص عليه
سياسة الخصوصية داخل التطبيق وعلى الموقع.

## ملاحظات أمان

- **كلمة المرور:** قوية، 12 حرفاً أو أكثر، ولا تُستعمل في مكان آخر. **تغييرها يُخرج كل الجلسات المفتوحة** على كل
  الأجهزة (نفّذ الأمر في الخطوة 3 بكلمة جديدة؛ لا حاجة لنشر جديد). الجلسة تدوم 12 ساعة، و«تسجيل الخروج» ينهيها فوراً
  حتى لو نُسخت.
- **المفتاح الخاص** يعيش فقط كسر في Cloudflare (`LICENSE_PRIVATE_JWK`): لا يُوضع في المستودع ولا في أي ملف يُرفع، ولا
  تعيده اللوحة ولا يُكتب في أي سجل. من يملكه يستطيع إصدار أكواد تفعيل، فاحتفظ بالملف الأصلي في مكان آمن خارج الإنترنت.
- **محاولات الدخول:** بعد 5 محاولات خاطئة من العنوان نفسه يتوقف الدخول منه 15 دقيقة. وإن جاءت 30 محاولة خاطئة من
  عناوين مختلفة يتوقف الدخول مؤقتاً من **المتصفحات الجديدة** فقط؛ أما المتصفح الذي دخلت منه سابقاً فيبقى يعمل، فادخل من
  جهازك المعتاد. كل محاولة دخول تُسجَّل في «سجل النشاط».
- **مفتاح النشر (API Token)** يبقى على جهازك فقط. إن ظننت أنه تسرّب، احذفه من صفحة API Tokens وأنشئ غيره.
- التنزيلات تُحتسب مرة واحدة لكل زائر في اليوم، فالأرقام في اللوحة لا تتضخم بإعادة التحميل.

## للمبرمج: الأسرار والتشغيل المحلي

| السر | أين | ما هو |
|---|---|---|
| `CLOUDFLARE_API_TOKEN` | بيئة جهاز النشر | مفتاح النشر (قالب **Edit Cloudflare Workers** + Account ← D1 ← Edit، الحساب حساب Dentora، وZone `raqeem.dev`) |
| `ADMIN_PASSWORD` | سر في الـ Worker | كلمة مرور لوحة التحكم، 12 حرفاً على الأقل |
| `LICENSE_PRIVATE_JWK` | سر في الـ Worker | JSON المفتاح الخاص من `secrets-for-user/dentora/license-private.jwk` |

انسخ `.dev.vars.example` إلى `.dev.vars` (لا يُحفظ في المستودع) واملأ القيمتين (المفتاح سطر JSON واحد بين علامتي
اقتباس مفردتين)، ثم:

```bash
npm run dev       # http://localhost:8787 ، قاعدة D1 محلية
npm run check     # بناء public/ + فحص الأنواع + wrangler deploy --dry-run (بدون مفتاح)
npm test          # اختبارات الوحدات (vitest)
npm run e2e       # اختبار شامل: يشغّل wrangler dev على قاعدة فارغة ويفحص الصفحات والتحميلات وكل مسارات API ولوحة التحكم ومفاتيح الترخيص وصفحة التفعيل في Chromium
```

`npm run build` (ويستدعيه `deploy` و`check` و`dev`) يجمع `public/` من `site/` ومن ملف APK الإصدار الحالي في
`../releases/Dentora-<version>.apk`، ومن مثبّت ويندوز (`../releases/Dentora-Setup-<version>.exe` أو `WINDOWS_SETUP`)
مقسَّماً إلى أجزاء من 20 ميغابايت (`WINDOWS_SETUP=none` يبنيه دون مثبّت). `public/` لا يُحفظ في المستودع.

`npm run e2e` يستعمل Playwright من `node_modules` التطبيق (`dental/`)، ويحتاج المنافذ 8831 إلى 8834 (يغيّرها
`E2E_PORT`). يبني `public/` دون مثبّت ويندوز، ثم يجرّب في آخره مثبّتاً بديلاً حجمه 45 ميغابايت، ويترك `public/` مبنياً دون مثبّت (`npm run build` يعيده). الصور واللقطات وسجلات الـ Worker تُكتب في `.wrangler/e2e/` (يغيّرها `E2E_OUT`)، ويطبع سطراً لكل فحص
وينتهي برمز خطأ إن فشل أي فحص.
