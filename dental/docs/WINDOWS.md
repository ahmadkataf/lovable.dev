# Dentora على ويندوز

نسخة ويندوز من Dentora هي نفس تطبيق الويب داخل نافذة سطح مكتب (Electron 44). تعمل دون إنترنت، وكل البيانات محفوظة على
الجهاز نفسه. يدعم Windows 10 و Windows 11 (64-بت).

ينتج البناء ملفين:

| الملف | الاستخدام |
|---|---|
| `Dentora-Setup-<الإصدار>.exe` | برنامج التثبيت (الموصى به): يختار المستخدم مجلد التثبيت، وتُنشأ اختصارات على سطح المكتب وفي قائمة ابدأ، ولا يحتاج صلاحيات مدير. |
| `Dentora-Portable-<الإصدار>.exe` | نسخة محمولة تعمل دون تثبيت (للتجربة أو العرض). تبدأ أبطأ قليلاً لأنها تفك نفسها عند كل تشغيل. |

---

## 1. أسهل طريقة: البناء عبر GitHub Actions

1. في GitHub افتح تبويب **Actions** ← **Dentora Windows** ← **Run workflow**.
2. اكتب رقم الإصدار (مثل `1.2.0`) أو اتركه فارغاً لاستخدام الرقم المكتوب في `dental/package.json`.
3. بعد انتهاء التشغيل (حوالي 10 دقائق) افتحه وانزل إلى قسم **Artifacts** ونزّل **Dentora-windows** (ملف zip يحوي ملفات ‎`.exe`).

بديل: إنشاء وسم يبدأ بـ `dentora-v` يبني الإصدار تلقائياً:

```bash
git tag dentora-v1.2.0
git push origin dentora-v1.2.0
```

تُحفظ الملفات في Actions مدة 90 يوماً؛ احتفظ بنسخة من كل إصدار تسلّمه للعيادات.

## 2. البناء محلياً على حاسوب ويندوز

المتطلبات: [Node.js 22 LTS](https://nodejs.org) و [Git](https://git-scm.com). ثم في PowerShell أو موجه الأوامر:

```powershell
git clone <repository-url>
cd <repository>\dental
npm ci
npm run electron:build
```

تظهر الملفات في المجلد `dental\release\`.

أوامر مفيدة أخرى:

```powershell
npm run electron:dev                       # build the web app and open it in Electron (no installer)
npx electron-builder --win --dir           # unpacked app only: release\win-unpacked\Dentora.exe
$env:DENTORA_DEV=1; npm run electron:dev   # same, with Developer Tools (F12) in the View menu
node scripts/qa/electron.mjs               # automated checks of the desktop shell (window, bridge, data after restart)
```

لتغيير رقم الإصدار: عدّل `"version"` في `dental/package.json` (يظهر في البرنامج وفي أسماء الملفات).

> على Linux يمكن بناء `--win --dir` والنسخة المحمولة (`npx electron-builder --win portable`)، أما برنامج التثبيت NSIS فيحتاج
> wine، لذلك استخدم GitHub Actions أو حاسوب ويندوز.

## 3. التثبيت في العيادة

1. شغّل `Dentora-Setup-<الإصدار>.exe`. تظهر واجهة التثبيت بالعربية إن كانت لغة ويندوز عربية، وإلا بالإنجليزية.
2. **تحذير SmartScreen**: ما دام البرنامج غير موقَّع رقمياً سيظهر "حمى Windows جهاز الكمبيوتر" عند أول تشغيل.
   اضغط **مزيد من المعلومات** ثم **تشغيل على أي حال**. هذا طبيعي للبرامج غير الموقعة (انظر "التوقيع الرقمي" أدناه).
3. اختر مجلد التثبيت (الافتراضي داخل حساب المستخدم، فلا حاجة لصلاحيات المدير)، ثم يفتح Dentora تلقائياً.
4. في أول تشغيل يظهر معالج الإعداد: بيانات العيادة، ثم حساب المدير ورمز PIN.

**التحديث إلى إصدار أحدث:** خذ نسخة احتياطية، ثم شغّل برنامج التثبيت الجديد فوق القديم. البيانات تبقى كما هي.

**إلغاء التثبيت** (الإعدادات ← التطبيقات) يحذف البرنامج فقط، ولا يحذف بيانات المرضى أبداً.

اختصارات مفيدة: `Ctrl +` / `Ctrl -` / `Ctrl 0` للتكبير والتصغير والحجم الطبيعي (يُحفظ مستوى التكبير)، `F11` ملء الشاشة،
`Ctrl K` البحث السريع، و`Alt` يُظهر شريط القوائم. فتح Dentora مرة ثانية لا يفتح نسخة جديدة بل يُظهر النافذة المفتوحة.

## 4. أين تُحفظ البيانات؟

كل بيانات العيادة (المرضى، المواعيد، الفواتير، الصور والأشعة، الإعدادات) في مجلد المستخدم:

```text
%APPDATA%\Dentora
(= C:\Users\<user name>\AppData\Roaming\Dentora)
```

| داخل المجلد | المحتوى |
|---|---|
| `IndexedDB\` | قاعدة البيانات نفسها: كل السجلات والملفات المرفقة |
| `Local Storage\` | تفضيلات صغيرة (اللغة، الخط، الجلسة) |
| `window-state.json` | حجم النافذة ومكانها ومستوى التكبير |
| `logs\main.log` | سجل تقني يفيد الدعم الفني عند حدوث مشكلة |

ملاحظات مهمة:

- البيانات **لكل مستخدم ويندوز**: إن دخل شخص آخر بحساب ويندوز مختلف فسيرى عيادة فارغة. استخدموا حساب ويندوز واحداً على حاسوب العيادة.
- كل حاسوب قاعدة بيانات مستقلة؛ لا توجد مزامنة بين الأجهزة (لا خادم). اختاروا حاسوباً رئيسياً واحداً للعيادة.
- النسخة المحمولة تستخدم المجلد نفسه، فالانتقال منها إلى النسخة المثبتة لا يضيّع شيئاً.
- لا تحذف هذا المجلد ولا تعدّل محتواه يدوياً.

## 5. النسخ الاحتياطي (مهم جداً)

البيانات موجودة على هذا الحاسوب فقط؛ إن تعطل القرص أو سُرق الجهاز ضاعت معه. لذلك:

1. **من داخل البرنامج** (الطريقة الأساسية): الإعدادات ← النسخ الاحتياطي ← تصدير. يُحفظ ملف ‎`.json` واحد يحوي كل الجداول والملفات المرفقة.
   والاستعادة من الشاشة نفسها (تحلّ محل البيانات الحالية بعد التأكيد).
2. **وتيرة مقترحة**: نسخة يومية في نهاية الدوام، ونسخة أسبوعية على وسيط خارجي.
3. **قاعدة 3-2-1**: ثلاث نسخ، على وسيطين مختلفين (مثلاً فلاشة USB وقرص خارجي)، وواحدة خارج العيادة (Google Drive أو OneDrive أو في المنزل).
4. **جرّب الاستعادة** مرة كل بضعة أشهر على حاسوب آخر للتأكد من أن النسخ سليمة.
5. خذ نسخة **قبل كل تحديث** وقبل نقل البرنامج إلى حاسوب جديد.
6. ملف النسخة يحوي بيانات طبية سرية: احفظه في مكان آمن ولا ترسله عبر قنوات غير موثوقة.

نسخة إضافية كاملة للمجلد (للخبراء): أغلق Dentora تماماً ثم انسخ المجلد `%APPDATA%\Dentora` كاملاً. تصلح لإرجاع الحاسوب نفسه إلى حالة سابقة،
أما النقل إلى حاسوب جديد فيكون بملف النسخة الاحتياطية من داخل البرنامج.

**الانتقال إلى حاسوب جديد:** صدّر نسخة احتياطية من الحاسوب القديم ← ثبّت Dentora على الجديد ← استورد النسخة ← اطلب رمز تفعيل جديداً
(رقم الجهاز يتغير، انظر القسم التالي).

## 6. الفترة التجريبية والترخيص ورقم الجهاز

- عند أول تشغيل تبدأ **فترة تجريبية مدتها 7 أيام** بكامل المزايا، ويظهر شريط أعلى الشاشة بعدد الأيام المتبقية.
- بعد انتهائها ينتقل البرنامج إلى **وضع القراءة فقط**: كل البيانات ظاهرة ويمكن تصديرها، لكن الإضافة والتعديل متوقفان حتى التفعيل. لا تُحذف أي بيانات.
- **رقم الجهاز**: يظهر في الإعدادات ← الترخيص (8 رموز مثل `7KQ2-M9XD`). يُشتق على ويندوز من معرّف ويندوز الثابت للجهاز (MachineGuid)
  بعد تشفيره باتجاه واحد، فلا يُرسل المعرّف الحقيقي إلى أي مكان. الرقم نفسه لكل حسابات ويندوز على الجهاز، ولا يتغير بإعادة تثبيت
  Dentora أو تحديثه. يتغير فقط عند إعادة تثبيت ويندوز أو تغيير الحاسوب.
- **التفعيل**: ترسل العيادة رقم الجهاز إلى البائع، فيعيد رمز تفعيل من 16 رمزاً (`XXXX-XXXX-XXXX-XXXX`) يُدخل في الإعدادات ← الترخيص.
  التحقق يتم داخل البرنامج دون إنترنت. الرمز مرتبط بهذا الجهاز فقط، وقد يكون لمدة محددة أو مدى الحياة (الخطة Standard أو Pro).
- رمز التفعيل لا يعمل على حاسوب آخر؛ لكل حاسوب رقم جهاز ورمز خاص به.
- عند إعادة تثبيت ويندوز أو تبديل الحاسوب: صدّر نسخة احتياطية أولاً، ثم أرسل رقم الجهاز الجديد إلى البائع لتحصل على رمز جديد.

## 7. التوقيع الرقمي (اختياري)

البرنامج غير الموقَّع يعمل بشكل كامل، والفرق الوحيد هو تحذير SmartScreen في أول تشغيل. لإزالته:

1. اشترِ شهادة توقيع برمجيات (Code Signing Certificate)، ويُفضَّل نوع EV لأنه يزيل التحذير فوراً.
2. في GitHub: Settings ← Secrets and variables ← Actions، أضف:
   - `CSC_LINK`: ملف الشهادة ‎`.pfx` مرمَّزاً بـ base64
     (`[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard` في PowerShell)
   - `CSC_KEY_PASSWORD`: كلمة مرور الشهادة
3. عدّل `publisherName` في `dental/electron-builder.yml` ليطابق اسم "Issued to" في الشهادة.

للتوقيع المحلي على ويندوز يكفي تعريف المتغيرين نفسيهما قبل `npm run electron:build`:

```powershell
$env:CSC_LINK="C:\path\to\cert.pfx"; $env:CSC_KEY_PASSWORD="..."; npm run electron:build
```

## 8. حل المشكلات

| المشكلة | الحل |
|---|---|
| النافذة بيضاء أو سوداء على حاسوب قديم | شغّل البرنامج مع إيقاف تسريع الرسوميات: `"%LOCALAPPDATA%\Programs\Dentora\Dentora.exe" --disable-gpu` (يمكن إضافة الخيار إلى خصائص الاختصار) |
| البرنامج لا يفتح أو يُغلق فجأة | أرسل ملف `%APPDATA%\Dentora\logs\main.log` إلى الدعم الفني |
| الخط صغير أو كبير | `Ctrl +` أو `Ctrl -`، و`Ctrl 0` للعودة إلى الحجم الطبيعي |
| ظهرت عيادة فارغة فجأة | تأكد أنك داخل حساب ويندوز نفسه المعتاد؛ وإن لزم استعد آخر نسخة احتياطية |
| انتهت التجربة والبيانات لا تُعدَّل | فعّل البرنامج من الإعدادات ← الترخيص؛ البيانات سليمة |

## للمطورين

| الملف | الدور |
|---|---|
| `electron/main.cjs` | العملية الرئيسية: النافذة وحفظ حالتها، القائمة، CSP، حماية التنقل والروابط الخارجية، معالجات IPC |
| `electron/preload.cjs` | الجسر `window.dentora` (مطابق لـ `ElectronBridge` في `src/platform/index.ts`) |
| `electron-builder.yml` | إعدادات الحزم: NSIS + Portable، اللغات، الأيقونات، عدم حذف البيانات عند الإلغاء |
| `build/` | الأيقونات: `icon.png` (512) و `icon.ico` (16–256) |
| `scripts/qa/electron.mjs` | فحص آلي بـ Playwright لنافذة Electron والجسر واستمرار البيانات |
| `.github/workflows/dentora-windows.yml` | البناء على `windows-latest` ورفع الملفات كـ Artifact |

إعادة توليد الأيقونات بعد تغيير `public/icon.svg`:

```bash
node scripts/make-icons.mjs build 16 20 24 32 40 48 64 128 256 512
cp build/icon-512.png build/icon.png
python3 build/make-ico.py
```

الفحص الآلي على Linux (يحتاج شاشة افتراضية) وعلى الحزمة المبنية:

```bash
npm run build && xvfb-run -a node scripts/qa/electron.mjs
npx electron-builder --win --dir && QA_APP=release/win-unpacked/resources/app.asar xvfb-run -a node scripts/qa/electron.mjs
```

متغيرات البيئة: `DENTORA_DEV=1` (أدوات المطوّر)، `DENTORA_USER_DATA=<dir>` (مجلد بيانات منفصل للتجارب)،
`DENTORA_DISABLE_GPU=1` أو الخيار `--disable-gpu` (رسم برمجي دون كرت الشاشة).

قواعد الأمان المطبقة: `contextIsolation` و`sandbox` مفعّلان و`nodeIntegration` معطّل؛ سياسة CSP صارمة (`script-src 'self'`)؛ أي رابط
`http(s)`/`mailto`/`tel` يفتح في المتصفح أو التطبيق الافتراضي؛ لا يمكن للصفحة مغادرة `dist/index.html`؛ ونوافذ العرض (`blob:`) لا تصل إلى الجسر.
