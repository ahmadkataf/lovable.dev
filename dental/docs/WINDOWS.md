# Dentora على ويندوز

نسخة ويندوز من Dentora هي نفس تطبيق الويب داخل نافذة سطح مكتب (Electron 44). تعمل دون إنترنت، وكل البيانات محفوظة على
الجهاز نفسه. لا تتصل بالإنترنت إلا إذا فعّلتها العيادة بمفتاح ترخيص، فتُرسل حينها المفتاح ورقم الجهاز فقط إلى `dentora.raqeem.dev`
مرة واحدة لاستلام رمز التفعيل. يدعم Windows 10 و Windows 11 (64-بت).

ينتج البناء ملفين:

| الملف | الاستخدام |
|---|---|
| `Dentora-Setup-<الإصدار>.exe` | برنامج التثبيت (الموصى به): يثبّت البرنامج لمستخدم ويندوز الحالي في `%LOCALAPPDATA%\Programs\Dentora` (يمكن تغيير المجلد)، وتُنشأ اختصارات على سطح المكتب وفي قائمة ابدأ، ولا يحتاج صلاحيات مدير ولا يسأل «لكل المستخدمين أم لي وحدي». |
| `Dentora-Portable-<الإصدار>.exe` | نسخة محمولة تعمل دون تثبيت (للتجربة أو العرض). تبدأ أبطأ قليلاً لأنها تفك نفسها عند كل تشغيل. |

---

## 1. أسهل طريقة: البناء عبر GitHub Actions

1. في GitHub افتح تبويب **Actions** ← **Dentora Windows** ← **Run workflow**.
2. اكتب رقم الإصدار (مثل `1.2.0`) أو اتركه فارغاً لاستخدام الرقم المكتوب في `dental/package.json`.
3. بعد انتهاء التشغيل (حوالي 10 دقائق) افتحه وانزل إلى قسم **Artifacts** ونزّل **Dentora-windows** (ملف zip يحوي ملفات ‎`.exe`).

بديل: إنشاء وسم يبدأ بـ `dentora-v` يبني الإصدار تلقائياً:

```bash
git tag dentora-v1.2.0
git push origin dentora-v1.2.0
```

تُحفظ الملفات في Actions مدة 90 يوماً؛ احتفظ بنسخة من كل إصدار تسلّمه للعيادات.

## 2. البناء محلياً على حاسوب ويندوز

المتطلبات: [Node.js 22 LTS](https://nodejs.org) و [Git](https://git-scm.com). ثم في PowerShell أو موجه الأوامر:

```powershell
git clone <repository-url>
cd <repository>\dental
npm ci
npm run electron:build
```

تظهر الملفات في المجلد `dental\release\`.

أوامر مفيدة أخرى:

```powershell
npm run electron:dev                       # build the web app and open it in Electron (no installer)
npx electron-builder --win --dir           # unpacked app only: release\win-unpacked\Dentora.exe
$env:DENTORA_DEV=1; npm run electron:dev   # same, with Developer Tools (F12) in the View menu (development only)
$env:VITE_QA=1; npx vite build --outDir $env:TEMP\dist-qa; $env:VITE_QA=$null
$env:QA_DIST="$env:TEMP\dist-qa"; node scripts/qa/electron.mjs   # automated checks of the desktop shell (a QA build: window, bridge, data after restart)
```

لتغيير رقم الإصدار: عدّل `"version"` في `dental/package.json` (يظهر في البرنامج وفي أسماء الملفات).

> على Linux يمكن بناء `--win --dir` والنسخة المحمولة (`npx electron-builder --win portable`)، أما برنامج التثبيت NSIS فيحتاج
> wine، لذلك استخدم GitHub Actions أو حاسوب ويندوز.

## 3. التثبيت في العيادة

1. شغّل `Dentora-Setup-<الإصدار>.exe`. تظهر واجهة التثبيت بالإنجليزية إن كانت لغة ويندوز الإنجليزية، وبالعربية في غير ذلك.
   أول صفحة فيها **شروط الاستخدام** (بالعربية ثم الإنجليزية، من `build/license.txt`) ويجب قبولها للمتابعة.
2. **إن كان البرنامج غير موقَّع رقمياً**:
   - على حاسوب Windows 11 جديد يكون **Smart App Control** مفعّلاً غالباً، وهو **يمنع** تشغيل برنامج التثبيت غير الموقَّع
     ولا يقدّم زر «تشغيل على أي حال». الحل هو التوقيع (القسم 7). لا تطلب من العيادة إيقاف Smart App Control من «أمن Windows»:
     إنه قرار أمني يخص جهازها، وقد لا يمكن إعادة تشغيله بعد ذلك دون إعادة ضبط ويندوز.
   - في غير ذلك يُظهر **SmartScreen** رسالة «حمى Windows جهاز الكمبيوتر»: **مزيد من المعلومات** ثم **تشغيل على أي حال**.
3. يظهر مباشرة اختيار مجلد التثبيت (الافتراضي `%LOCALAPPDATA%\Programs\Dentora` داخل حساب المستخدم، فلا حاجة لصلاحيات المدير)،
   ثم يفتح Dentora تلقائياً. إن كانت نسخة قديمة مثبّتة «لكل المستخدمين» فيُحدَّث البرنامج في مكانه نفسه.
4. في أول تشغيل يظهر معالج الإعداد: اللغة، بيانات العيادة، العملة والدوام والبلد وأسماء الأشهر، ثم حساب المدير ورمز PIN،
   ثم المراجعة والموافقة على شروط الاستخدام وسياسة الخصوصية.
   إن كانت لديك نسخة احتياطية سابقة فاضغط في الخطوة الأولى **«استعد بياناتك من نسخة احتياطية»**.
5. يُطلب رمز PIN عند **كل** فتح للبرنامج (الدخول محفوظ لهذا التشغيل فقط)، ويُقفل تلقائياً بعد مدة الخمول المختارة في الإعدادات.

**التحديث إلى إصدار أحدث:** خذ نسخة احتياطية، ثم شغّل برنامج التثبيت الجديد فوق القديم. البيانات تبقى كما هي.

**إلغاء التثبيت** (إعدادات ويندوز ← التطبيقات) يحذف البرنامج فقط، ولا يحذف بيانات المرضى أبداً.

اختصارات مفيدة: `Ctrl +` / `Ctrl -` / `Ctrl 0` للتكبير والتصغير والحجم الطبيعي (يُحفظ مستوى التكبير)، `F11` ملء الشاشة،
`Ctrl P` طباعة الشاشة الحالية، `Ctrl K` البحث السريع، و`Alt` يُظهر شريط القوائم. **الزر الأيمن للفأرة** داخل أي حقل يُظهر
قص / نسخ / لصق / تحديد الكل (مفيد للصق رمز التفعيل من واتساب)، وفوق نص محدد يُظهر نسخ. فتح Dentora مرة ثانية لا يفتح نسخة
جديدة بل يُظهر النافذة المفتوحة. تعود النافذة إلى حجمها ومكانها السابقين، وإن صارت الشاشة أصغر (حاسوب محمول فُصل عن شاشة كبيرة)
أو أُزيلت شاشة ثانية فتُعرض النافذة كاملة على الشاشة الحالية (ومكبّرة إن كانت أكبر منها).

**الطباعة**: أزرار الطباعة في البرنامج (الفاتورة، الوصفة، خطة العلاج، مخطط الأسنان) تفتح نافذة الطباعة المعتادة في ويندوز.
لحفظ المستند كملف PDF بدلاً من طباعته اختر الطابعة **Microsoft Print to PDF**.

## 4. أين تُحفظ البيانات؟

كل بيانات العيادة (المرضى، المواعيد، الفواتير، الصور والأشعة، الإعدادات) في مجلد المستخدم:

```text
%APPDATA%\Dentora
(= C:\Users\<user name>\AppData\Roaming\Dentora)
```

| داخل المجلد | المحتوى |
|---|---|
| `IndexedDB\` | قاعدة البيانات نفسها: كل السجلات والملفات المرفقة |
| `Local Storage\` | تفضيلات صغيرة (اللغة، الخط، الجلسة) |
| `window-state.json` | حجم النافذة ومكانها ومستوى التكبير |
| `device-id.json` | معرّف هذا التثبيت الذي يُشتق منه رقم الجهاز (لا تحذفه ولا تنسخه إلى حاسوب آخر) |
| `logs\main.log` | سجل تقني يفيد الدعم الفني عند حدوث مشكلة |

ملاحظات مهمة:

- البيانات **لكل مستخدم ويندوز**: إن دخل شخص آخر بحساب ويندوز مختلف فسيرى عيادة فارغة. استخدموا حساب ويندوز واحداً على حاسوب العيادة.
- كل حاسوب قاعدة بيانات مستقلة؛ لا توجد مزامنة بين الأجهزة (لا خادم). اختاروا حاسوباً رئيسياً واحداً للعيادة.
- النسخة المحمولة تستخدم المجلد نفسه، فالانتقال منها إلى النسخة المثبتة لا يضيّع شيئاً.
- لا تحذف هذا المجلد ولا تعدّل محتواه يدوياً.

## 5. النسخ الاحتياطي (مهم جداً)

البيانات موجودة على هذا الحاسوب فقط؛ إن تعطل القرص أو سُرق الجهاز ضاعت معه. لذلك:

1. **من داخل البرنامج** (الطريقة الأساسية): الإعدادات ← **النسخ الاحتياطي** ← **«تصدير نسخة احتياطية»**، ثم اختر مكان الحفظ
   (فلاشة USB مثلاً). يُحفظ ملف واحد مثل `dentora-backup-2026-10-11-0930.dentora`: أرشيف ZIP فيه كل جداول البيانات، وكل صورة
   أو أشعة أو PDF في ملف مستقل بحجمه الأصلي، وملف وصف (manifest) بالأعداد. يمكن **حمايته بكلمة مرور** (تشفير AES-256-GCM؛
   من دونها لا يُفتح الملف أبداً، فاحفظها). بعد الكتابة يقرأ البرنامج الملف من القرص ويتحقق من حجمه وبصمته قبل أن يقول «تم الحفظ»؛
   وإن امتلأ القرص أو فشلت الكتابة يقول ذلك صراحة.
   والاستعادة من الشاشة نفسها: **«استعادة نسخة احتياطية»**: يُفحص الملف كله أولاً (يُطلب كلمة المرور إن كان محمياً)، ثم يحلّ محل
   البيانات الحالية دفعة واحدة بعد التأكيد، أو لا يتغير شيء. النسخ القديمة بصيغة `.json` ما زالت تُستعاد. يبقى تفعيل هذا الجهاز
   وتاريخ بداية تجربته كما هما.
2. **وتيرة مقترحة**: نسخة يومية في نهاية الدوام، ونسخة أسبوعية على وسيط خارجي.
3. **قاعدة 3-2-1**: ثلاث نسخ، على وسيطين مختلفين (مثلاً فلاشة USB وقرص خارجي)، وواحدة خارج العيادة (Google Drive أو OneDrive أو في المنزل).
4. **جرّب الاستعادة** مرة كل بضعة أشهر على حاسوب آخر للتأكد من أن النسخ سليمة.
5. خذ نسخة **قبل كل تحديث** وقبل نقل البرنامج إلى حاسوب جديد.
6. ملف النسخة يحوي بيانات طبية سرية: احفظه في مكان آمن ولا ترسله عبر قنوات غير موثوقة.

نسخة إضافية كاملة للمجلد (للخبراء): أغلق Dentora تماماً ثم انسخ المجلد `%APPDATA%\Dentora` كاملاً. تصلح لإرجاع الحاسوب نفسه إلى حالة سابقة،
أما النقل إلى حاسوب جديد فيكون بملف النسخة الاحتياطية من داخل البرنامج.

**الانتقال إلى حاسوب جديد:** صدّر نسخة احتياطية من الحاسوب القديم ← ثبّت Dentora على الجديد ← في معالج الإعداد اضغط
«استعد بياناتك من نسخة احتياطية» ← اطلب رمز تفعيل جديداً (رقم الجهاز يتغير، انظر القسم التالي).

## 6. الفترة التجريبية والترخيص ورقم الجهاز

- عند أول تشغيل تبدأ **فترة تجريبية مدتها 7 أيام** بكامل المزايا، ويظهر شريط أعلى الشاشة بعدد الأيام المتبقية وزر «تفعيل الآن».
- بعد انتهائها ينتقل البرنامج إلى **وضع القراءة فقط**: كل البيانات ظاهرة ويمكن تصديرها، لكن الإضافة والتعديل متوقفان حتى التفعيل. لا تُحذف أي بيانات.
- **رقم الجهاز**: يظهر في الإعدادات ← الترخيص (8 رموز مثل `7KQ2-M9XD`). يُشتق على ويندوز من معرّف ويندوز الثابت للجهاز (MachineGuid)
  بعد تشفيره باتجاه واحد، فلا يُرسل المعرّف الحقيقي إلى أي مكان. الرقم نفسه لكل حسابات ويندوز على الجهاز، ولا يتغير بإعادة تثبيت
  Dentora أو تحديثه. يُحفظ المعرّف عند أول تشغيل في `device-id.json` داخل مجلد البيانات، فلا يتغيّر الرقم إذا تعذّرت قراءة
  MachineGuid يوماً ما (سياسة تمنع أداة السجل reg.exe، برنامج حماية، بطء الجهاز). يتغير فقط عند إعادة تثبيت ويندوز أو تغيير الحاسوب
  (ونقل مجلد البيانات إلى حاسوب آخر يعطي رقم ذلك الحاسوب، لا رقم الحاسوب القديم).
- **التفعيل**: ترسل العيادة رقم الجهاز إلى البائع، فيعيد **رمز تفعيل موقّعاً من 112 خانة** (حروف إنجليزية وأرقام، يصل عادة في رسالة
  واتساب أو بريد). يُلصق كما هو في الإعدادات ← الترخيص (`Ctrl V` أو الزر الأيمن ← لصق)؛ المسافات والشرطات وفواصل الأسطر وحالة الأحرف
  لا تهم. التحقق يتم داخل البرنامج دون إنترنت. الرمز مرتبط بهذا الجهاز فقط، وقد يكون لمدة محددة أو مدى الحياة (الخطة Standard أو Pro).
- **التفعيل بمفتاح ترخيص** (من الإصدار 1.1.0): قد يبيع البائع **مفتاحاً** (`XXXX-XXXX-XXXX-XXXX`) دون أن يطلب رقم الجهاز. يُلصق
  المفتاح في الحقل نفسه ثم «تفعيل»، فيرسل البرنامج المفتاح ورقم الجهاز فقط إلى `https://dentora.raqeem.dev/api/activate` ويستلم رمز
  التفعيل العادي، ويتحقق منه بنفسه كأي رمز يرسله البائع، ثم يعمل دون إنترنت كما سبق. يلزم اتصال بالإنترنت هذه المرة فقط؛ وإن تعذّر
  يعرض البرنامج زر «التفعيل من المتصفح» الذي يفتح صفحة التفعيل (`https://dentora.raqeem.dev/activate`) ورقم الجهاز مكتوب فيها، ويمكن
  أيضاً فتح الصفحة من جهاز آخر متصل وكتابة رقم الجهاز، ثم لصق الرمز الناتج في البرنامج. المفتاح يعمل على حاسوب واحد.
- رمز التفعيل لا يعمل على حاسوب آخر؛ لكل حاسوب رقم جهاز ورمز خاص به.
- عند إعادة تثبيت ويندوز أو تبديل الحاسوب: صدّر نسخة احتياطية أولاً، ثم أرسل رقم الجهاز الجديد إلى البائع لتحصل على رمز جديد.
- **نسيان رمز الدخول (PIN):** إن نسي المدير الوحيد رمزه يرسل رقم الجهاز إلى البائع، فيصنع له **رمز إعادة تعيين**
  (`node scripts/code-generator.mjs reset <رقم-الجهاز>` أو قسم الإعادة في صفحة المولّد) يعمل على هذا الجهاز اليوم وغداً ولمرة واحدة:
  شاشة الدخول ← «نسيت رمز الدخول؟» ← «لدي رمز إعادة تعيين»، ثم رمز جديد. لا تُمس بيانات المرضى.

## 7. التوقيع الرقمي (ضروري قبل البيع)

البرنامج غير الموقَّع يعمل، لكن:
- **Smart App Control** (مفعّل افتراضياً على كثير من أجهزة Windows 11 الجديدة) **يمنع** تشغيل برنامج التثبيت غير الموقَّع نهائياً، ولا يمكن
  استثناء برنامج بعينه. عيادة اشترت حاسوباً جديداً قد لا تستطيع التثبيت أصلاً.
- **SmartScreen** يُظهر تحذيراً عند أول تشغيل، ويختفي تدريجياً كلما اكتسبت **شهادتك** سمعة (عدد تنزيلات وتثبيتات دون شكاوى).
  منذ 2024 لم تعد شهادة EV تزيل التحذير فوراً؛ السمعة تُبنى مع الوقت لأي نوع، فاستخدم **الشهادة نفسها** في كل إصدار.

ما يُوقَّع: `Dentora.exe` وبرنامج التثبيت وبرنامج الإلغاء والنسخة المحمولة، مع ختم زمني (timestamp) يُبقي التوقيع صالحاً بعد انتهاء الشهادة.
يفعل electron-builder ذلك تلقائياً متى وُجدت بيانات التوقيع.

### الخيار 1 (الموصى به): Azure Trusted Signing
خدمة توقيع سحابية من Microsoft (حوالي 10 دولارات شهرياً)، المفتاح محفوظ لدى Microsoft فلا ملف يُسرق، وتعمل على GitHub Actions مباشرة.
متاحة للشركات والمؤسسات في الولايات المتحدة وكندا والاتحاد الأوروبي والمملكة المتحدة، وللأفراد في الولايات المتحدة وكندا فقط (تحقّق من
الشروط الحالية عند التسجيل).
1. في Azure: أنشئ حساب **Trusted Signing**، أكمل التحقق من الهوية، وأنشئ **Certificate Profile** من نوع Public Trust.
2. أنشئ App registration (Microsoft Entra ID) مع سر (client secret)، وأعطه دور **Trusted Signing Certificate Profile Signer** على الحساب.
3. في GitHub ← Settings ← Secrets and variables ← Actions أضف:
   `AZURE_TENANT_ID`، `AZURE_CLIENT_ID`، `AZURE_CLIENT_SECRET`، `AZURE_TS_ENDPOINT` (مثل `https://weu.codesigning.azure.net`)،
   `AZURE_TS_ACCOUNT` (اسم الحساب)، `AZURE_TS_PROFILE` (اسم الـ Certificate Profile)، `AZURE_TS_PUBLISHER` (اسم الناشر كما في الشهادة، CN).
4. شغّل سير العمل **Dentora Windows**: يوقّع تلقائياً ويكتب في الملخص «Signing with Azure Trusted Signing».
5. عدّل `publisherName` في `dental/electron-builder.yml` إلى اسم الناشر نفسه.

### الخيار 2: شهادة OV أو EV من جهة إصدار (CA)
منذ يونيو 2023 لا تُسلَّم مفاتيح توقيع البرامج في ملف ‎`.pfx` يمكن تصديره؛ المفتاح يكون على **مفتاح USB (token)** أو **HSM سحابي**:
- **سحابي** (يعمل مع GitHub Actions): SSL.com eSigner، DigiCert KeyLocker، Certum SimplySign. كل منها يقدّم أداة أو مزوّد مفاتيح لـ
  `signtool`؛ اتبع دليل المزوّد لـ electron-builder (عادة عبر `win.signtoolOptions.sign` بسكربت صغير يستدعي أداتهم، أو `certificateSha1`
  بعد تثبيت مزوّد المفاتيح على جهاز البناء).
- **مفتاح USB** (التوقيع على حاسوب ويندوز لديك): ركّب المفتاح وبرنامجه، ثم ابنِ مع بصمة الشهادة:
  ```powershell
  npx electron-builder --win -c.win.signtoolOptions.certificateSha1=<THUMBPRINT> -c.win.signtoolOptions.publisherName="<CN>"
  ```
- **ملف ‎.pfx** (فقط إن أعطتك الجهة ملفاً قابلاً للتصدير): أضف السرّين `CSC_LINK` (الملف بترميز base64:
  `[Convert]::ToBase64String([IO.File]::ReadAllBytes("cert.pfx")) | Set-Clipboard`) و`CSC_KEY_PASSWORD`، أو عرّفهما محلياً قبل
  `npm run electron:build`.

في كل الحالات: عدّل `publisherName` في `dental/electron-builder.yml` ليطابق اسم "Issued to" في الشهادة، وتحقق بعد البناء:
خصائص الملف ← **التوقيعات الرقمية** يجب أن تُظهر اسمك وختماً زمنياً، أو `signtool verify /pa /v Dentora-Setup-<الإصدار>.exe`.

إعادة توليد الأيقونات بعد تغيير `public/icon.svg`:

```bash
node scripts/make-icons.mjs build 16 20 24 32 40 48 64 128 256 512
cp build/icon-512.png build/icon.png
python3 build/make-ico.py
```

الفحص الآلي على Linux (يحتاج شاشة افتراضية) وعلى الحزمة المبنية:

```bash
VITE_QA=1 npx vite build && xvfb-run -a node scripts/qa/electron.mjs
# a private QA build in a staged app folder (safe while other builds rewrite dist/)
VITE_QA=1 npx vite build --outDir /tmp/dist-x && QA_DIST=/tmp/dist-x QA_SHOTS=qa-shots/electron-x xvfb-run -a node scripts/qa/electron.mjs
VITE_QA=1 npx vite build && npx electron-builder --win --dir && QA_APP=release/win-unpacked/resources/app.asar xvfb-run -a node scripts/qa/electron.mjs
# then rebuild dist/ without VITE_QA (npm run build) before any build you hand to a clinic
```

يفحص النافذة والجسر والعزل وCSP (طلب التفعيل يصل إلى خادمه، والطلب نفسه إلى أي موقع آخر يُرفض) والروابط الخارجية (صفحة التفعيل
تُفتح في المتصفح) والحوار الأصلي للحفظ والفتح والطباعة (`Ctrl P`) وعرض PDF داخل البرنامج
والحافظة والواجهة الإنجليزية وكل الشاشات دون أخطاء، ومنع تشغيل نسخة ثانية، وبقاء البيانات وحجم النافذة بعد إعادة التشغيل.
على ويندوز يتأكد أيضاً أن رقم الجهاز مشتق من MachineGuid. الصور في `qa-shots/electron/`.

`scripts/qa/electron.mjs` يحتاج بناءً للفحص (`VITE_QA=1 npx vite build …`، فيه `window.__dentora`)؛ `npm run build` لا يضبط
`VITE_QA`، فالبرنامج المبني للبيع لا يعطي الصفحة أي وصول إلى قاعدة البيانات.

متغيرات البيئة: `DENTORA_DEV=1` (أدوات المطوّر، **في التطوير فقط**: `npm run electron:dev`؛ البرنامج المثبّت يتجاهله)،
`DENTORA_USER_DATA=<dir>` (مجلد بيانات منفصل للتجارب)، `DENTORA_DISABLE_GPU=1` أو الخيار `--disable-gpu` (رسم برمجي دون كرت الشاشة).

قواعد الأمان المطبقة: `contextIsolation` و`sandbox` مفعّلان و`nodeIntegration` معطّل؛ سياسة CSP صارمة (`script-src 'self'`،
`object-src 'none'`، `form-action 'none'`، و`connect-src` لا يسمح بعنوان على الإنترنت غير خادم التفعيل `https://dentora.raqeem.dev`)
يرسلها `main.cjs` (من `lib.cjs`) وهي نفسها في `index.html`؛ أي رابط
`http(s)`/`mailto`/`tel` يفتح في المتصفح أو التطبيق الافتراضي؛ لا يمكن للصفحة مغادرة `dist/index.html` (يُقارن العنوان بالمسار بعد فك
ترميزه، فيعمل الجسر ولو كان في مسار التثبيت أو اسم المستخدم `%` أو `#` أو حروف عربية)؛ ونوافذ العرض (`blob:`) لا تصل إلى الجسر.
والبرنامج المثبّت (لا نسخة التطوير):
- يرفض أن يبدأ مع `--remote-debugging-port` أو `--remote-debugging-pipe` أو `--inspect` أو `--js-flags` (بأي صيغة: `--` أو `-` أو `/`)،
  ولا يفتح أدوات المطوّر أبداً.
- **Electron fuses** في `Dentora.exe`: `RunAsNode` و`NODE_OPTIONS` و`--inspect` معطّلة، يحمّل الكود من `app.asar` فقط، ويتحقق من بصمة
  `app.asar` المضمّنة في `Dentora.exe` (أي تعديل على الأرشيف بعد البناء يمنع التشغيل). للتحقق:
  `npx @electron/fuses read --app release/win-unpacked/Dentora.exe`.
- لا يُحمّل قاموس التدقيق الإملائي من الإنترنت (التدقيق معطّل)، ولا يتصل بأي عنوان خارجي غير طلب التفعيل بمفتاح الترخيص.
  هذا الطلب تكفيه CSP: الصفحة `file://` فيحمل الطلب `Origin: null`، ويقبله الخادم لأنه يجيب `Access-Control-Allow-Origin: *`؛ ولا شيء
  آخر في `main.cjs` يعترضه (`webRequest` يضع CSP في صفحات `file://` فقط، وأذونات الصفحة لا تخص الطلبات، وحماية التنقل لا تخص `fetch`).
  أما صفحة التفعيل في الموقع فلا تُفتح داخل نافذة البرنامج أبداً: التنقل إليها يُلغى وتُفتح في المتصفح كأي رابط آخر.
- يمنح الصفحة إذن `persistent-storage` (مع الحافظة وملء الشاشة والإشعارات والكاميرا): `navigator.storage.persist()` عند البدء يجعل
  Chromium لا يحذف بيانات العيادة حين تقل مساحة القرص، وتظهر حالته في الإعدادات ← النسخ الاحتياطي.
- رقم الجهاز يأتي دائماً من `device-id.json`/MachineGuid عبر الجسر؛ إن لم يُجب الجسر لحظةً يُسأل مرة ثانية ثم يُستخدم آخر رقم
  قرأه البرنامج على هذا الجهاز، ولا يُخترع رقم عشوائي أبداً (يبطل التفعيل). إن لم يُقرأ من قبل تقول شاشة الترخيص ذلك مع «إعادة المحاولة».
- الطباعة على خلفية بيضاء (هوامش الفاتورة والوصفة لا تخرج رمادية).

لإعادة رسم صورة برنامج التثبيت بعد تغيير الشعار: `node build/make-installer-art.mjs`.
