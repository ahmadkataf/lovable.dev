## 3b. Developer account and payments — حساب المطوّر والدفع

**Account type: Organization.** Play Console Requirements §1.2: providers of health apps, including medical apps such as
electronic health records, "must register as an Organization". An Organization account needs a D-U-N-S number (free from
Dun & Bradstreet) and a verified organisation website (`raqeem.dev`). An existing personal account can be converted
(Play Console → Developer account → About you), then wait 72 hours before submitting; an Organization account also skips
the 12-tester / 14-day closed test that new personal accounts need.
/ نوع الحساب: **مؤسسة** (إلزامي للتطبيقات الطبية، ومنها السجلات الصحية). يحتاج رقم D-U-N-S مجانياً وموقعاً موثّقاً، ويمكن تحويل
الحساب الشخصي إليه ثم الانتظار 72 ساعة قبل الإرسال.

**Payments: a free, consumption-only app.** Dentora is published on Play as a free app with no in-app products. The
licence is sold outside Play (WhatsApp, the website), and the app only *unlocks* what was paid for elsewhere, by a licence
key or an activation code. Google allows this ("Play allows any app to be consumption-only… a user could… access content
paid for somewhere else", provided nothing "can be purchased from within the app"). What keeps it compliant:
- A copy installed from Google Play shows no price, no WhatsApp or e-mail request button, no "activate in the browser"
  button and no link to the website (help links included); it only says to send the device number to whoever sold the
  licence (`src/features/settings/seller.ts`, `help.ts`). Copies installed from the website show the seller box.
- The listing in every language mentions no price, no "buy" wording and no website or WhatsApp purchase route, but says
  plainly that a paid licence is required after the 7-day trial (Payments policy §6).
- Do not join Google's alternative-billing or external-links programs (US, EEA, billing choice): they need enrolment,
  Google's APIs and fees, and Dentora needs none of them.
/ **الدفع:** تطبيق مجاني «للاستهلاك فقط»: يُشترى الترخيص خارج Play ويفتحه التطبيق بالمفتاح أو الرمز. النسخة المثبتة من Play
لا تعرض سعراً ولا زر شراء ولا رابطاً للموقع، وبطاقة المتجر تقول إن ترخيصاً مدفوعاً يلزم بعد التجربة دون ذكر طريقة الدفع.

## 4. Data safety — أمان البيانات

What the app does (checked in the code): all clinic and patient data is stored in the app's private storage on the
device (IndexedDB in the WebView), and the app never sends it anywhere; there is no account, analytics, ads, crash
reporting or tracking; `allowBackup="false"` and `data_extraction_rules` keep the data out of Google's backup and
device-to-device transfer. The app contacts a server in one case only: when someone at the clinic activates it with a
**licence key** (Settings → Licence), it sends the key and the **device number** (a short number derived from a hash of
the Android ID, not the clinic's data) over HTTPS to the developer's activation server,
`https://dentora.raqeem.dev/api/activate`, once, and receives the activation code. The server keeps that device number
and the time of activation with the record of the sale, so that the key is refused on a second device. The Android
shell refuses every other network request: that one HTTPS address is the only one the app can reach (the INTERNET
permission is there because a WebView needs it, and for that request). When that request cannot get through, a copy
installed from Google Play only says so and asks to try again: it shows no link to the website, where the price is
(copies installed outside Play also offer the activation page in the browser).
Activating with an activation code from the seller needs no connection. Apart from that, data leaves the device only
when someone at the clinic chooses to: a WhatsApp message they review in WhatsApp, a printed page or PDF, an exported
backup or CSV file they save or share.

ما يرسله التطبيق: مفتاح الترخيص ورقم الجهاز فقط، إلى خادمنا عبر HTTPS، وعند التفعيل بمفتاح فقط. بيانات العيادة والمرضى لا
تخرج من التطبيق إلا بفعل يقوم به المستخدم (رسالة واتساب، طباعة، نسخة احتياطية أو ملف CSV).

| Play Console question | Answer | Why / السبب |
|---|---|---|
| Does your app collect or share any of the required user data types? | **Yes** | Play counts data as *collected* when the app sends it off the device. Activating with a licence key sends the device number and the key to the developer's server, which keeps the device number with the sale. Nothing else is collected: clinic and patient data never leave the device through the app, and transfers the user starts and expects (sharing a file, sending a WhatsApp message) are neither *collection* nor *sharing*. يُرسَل رقم الجهاز والمفتاح إلى خادمنا عند التفعيل بمفتاح، ولا شيء غيرهما |
| Is all of the user data collected by your app encrypted in transit? | **Yes** | HTTPS only: the shell lets through `https://dentora.raqeem.dev/api/activate` and nothing else, and the app's CSP allows no other server. عبر HTTPS فقط |
| Do you provide a way for users to request that their data be deleted? | **No** | The device number bound to a key is the record that the key has been used: deleting it would free the key for another device, and the control panel cannot delete a sale (it would take a manual change in the D1 database). Answer *Yes* only if you will handle such requests that way. The data on the device: Settings → Backup & data → Erase all data, or uninstalling. رقم الجهاز المرتبط بالمفتاح هو سجل استعماله، ولوحة التحكم لا تحذف سجلات البيع |

Resulting store label / ما سيظهر في المتجر: **No data shared with third parties · Data collected: Device or other IDs ·
Data is encrypted in transit · Data can't be deleted**.

**Internet address:** like any web request, the activation request reaches the server from an internet address. The
server's database records it only for a failed attempt, on its own (not with the key or the device number), counts it
for 15 minutes to stop anyone guessing keys, and deletes it with the next activation request after that; it is not
used to locate anyone, so it is not declared as a separate data type.
/ لا تسجّل قاعدة بيانات الخادم عنوان الإنترنت إلا عند المحاولة الفاشلة، وحده دون المفتاح أو رقم الجهاز، وتَعُدّه 15 دقيقة لمنع
تخمين المفاتيح، ثم تحذفه مع أول طلب تفعيل بعد ذلك.

**Encrypted backups (optional):** the backup file can be protected with a password (AES-256-GCM). That is an app
feature for the clinic's own copies, not part of the Data safety form (its "encrypted in transit" answer is about the
HTTPS activation request): mention it in the description (done above). / حماية النسخة الاحتياطية بكلمة مرور ميزة تُذكر في
الوصف، لا إجابة في نموذج أمان البيانات.

### Remaking the pictures — إعادة توليد الصور

```bash
cd dental
VITE_QA=1 npx vite build --outDir /tmp/dist-store                      # a QA build (the scripts need window.__dentora)
QA_DIST=/tmp/dist-store QA_PORT=4790 node store/scripts/shoot.mjs      # screenshots: store/screenshots/ (+ taller phone captures in $STORE_WORK)
node store/scripts/compose.mjs                                         # icon, feature graphics, framed set, website pictures
node store/scripts/check.mjs                                           # sizes, no alpha, counts and limits, no price wording
```

`shoot.mjs` takes `--devices=phone,tablet7,tablet10,desktop`, `--langs=ar,en` and `--screens=dashboard,…`;
`compose.mjs` takes `icon`, `feature`, `frames`, `web`. Both need Playwright's Chromium (`npx playwright install chromium`).
Look at every picture after a run: the demo data follows the fixed date, so the pictures stay the same unless the app
or the demo data changes.
