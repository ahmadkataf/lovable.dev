# خادم كاسب — التفعيل وصفحة الأكواد

الخادم هو الجهة الوحيدة التي يتصل بها كاسب بالإنترنت: يتحقق من كود التفعيل، ويربطه بالجهاز، ويعيد التحقق كل ست ساعات.
كل بيانات المحل (المنتجات، الفواتير، العملاء…) تبقى على جهاز العميل ولا تصل إلى هنا أبداً.

الخادم يعمل على Cloudflare (Worker + قاعدة بيانات D1) ضمن الخطة المجانية، ولا يحتاج أي صيانة.

## التشغيل لأول مرة (مرة واحدة فقط)

1. **حساب Cloudflare (مجاني):** سجّل في https://dash.cloudflare.com/sign-up
2. **رقم الحساب:** من لوحة Cloudflare افتح Workers & Pages، وانسخ **Account ID** من يمين الصفحة.
3. **مفتاح API:** من صورتك في الأعلى ← My Profile ← API Tokens ← Create Token ←
   اختر قالب **Edit Cloudflare Workers**، ثم أضف صلاحية **Account → D1 → Edit** ← Continue ← Create Token، وانسخ المفتاح.
4. **الأسرار في GitHub:** في المستودع ← Settings ← Secrets and variables ← Actions ← New repository secret، وأضف أربعة
   (الأولان مشتركان مع خادم Emar إن كان موجوداً، فلا تضفهما مرتين):
   | الاسم | القيمة |
   |---|---|
   | `CLOUDFLARE_API_TOKEN` | المفتاح من الخطوة 3 |
   | `CLOUDFLARE_ACCOUNT_ID` | الرقم من الخطوة 2 |
   | `KASEB_ADMIN_KEY` | كلمة سر صفحة الأكواد: طويلة وسرية (مثلاً 24 حرفاً ورقماً) |
   | `KASEB_LICENSE_SECRET` | نص عشوائي طويل (40 حرفاً على الأقل). منه يُشتق مفتاح توقيع التراخيص. **لا تغيّره أبداً بعد ذلك**، وإلا تتوقف كل التراخيص المفعّلة |
5. **التشغيل:** في المستودع ← Actions ← **Deploy Kaseb server** ← Run workflow.
   عند انتهائه يظهر في أعلى صفحة التشغيل تنبيهان: عنوان الخادم مثل `https://kaseb-api.<اسمك>.workers.dev`، والمفتاح العام.

بعدها يتحدّث الخادم تلقائياً كلما تغيّر شيء في `pos/server`.

## ما تعطيه لمن يبني التطبيق

التطبيق يُبنى على عنوان خادم بعينه ومفتاح عام بعينه، فلا تعمل معه أكواد من أي خادم آخر:

- **متغير المستودع `KASEB_API`:** في المستودع ← Settings ← Secrets and variables ← Actions ← تبويب **Variables** ← New repository variable،
  الاسم `KASEB_API` والقيمة عنوان الخادم (بدون شرطة مائلة في النهاية).
- **المفتاح العام:** يجلبه سير البناء من `<العنوان>/api/public-key` بنفسه، وتجده أيضاً في صفحة الأكواد ← إعدادات ← للمطوّر.

## صفحة الأكواد (لوحة البائع)

افتح `https://kaseb-api.<اسمك>.workers.dev/admin` وأدخل `KASEB_ADMIN_KEY`. يُحفظ المفتاح في متصفحك فقط. أربعة تبويبات:

- **لوحة:** كم كوداً أُنشئ وفُعّل، الأجهزة النشطة خلال أسبوع، التجارب الجارية، تفعيلات الأسبوع، ورسم للتفعيلات في آخر 14 يوماً، وآخر الأحداث
  (تفعيل، محاولة فاشلة وسببها، تجربة، تحرير جهاز، إجراءاتك أنت).
- **أكواد:** أنشئ من 1 إلى 100 كود دفعة واحدة: المدة (دائم / سنة / حتى تاريخ)، عدد الأجهزة لكل كود (1–5)، البائع وملاحظة.
  بعدها **نسخ الكل** (كود في كل سطر)، **نسخ رسالة للعميل** جاهزة للواتساب، أو **طباعة بطاقات** لتوزيعها.
  ابحث بالكود أو الملاحظة أو البائع أو رمز الجهاز، وصفّ بالحالة. اضغط أي كود لتفتح بطاقته: أجهزته (الاسم، النظام، الإصدار، آخر ظهور،
  رمز الجهاز) وسجل أحداثه، والإجراءات:
  - **إلغاء / إعادة الكود:** يتوقف التطبيق عند صاحبه عند أول تحقق (خلال ساعات) ويعود عند الإعادة.
  - **تحرير جهاز:** يفك ارتباط جهاز واحد ليُفعَّل الكود على جهاز جديد (نقل الترخيص).
  - **تمديد:** غيّر تاريخ الانتهاء أو اجعله دائماً. **الملاحظة والبائع**، و**عدد الأجهزة المسموح**.
- **الأجهزة:** كل جهاز فتح التطبيق، مرخّصاً كان أو في تجربة، مع رمز الجهاز والإصدار وآخر ظهور. اضغط الجهاز لترى تفاصيله وسجله،
  ولتحرّره من كوده أو **تمنحه كوداً** مباشرة: يُنشأ كود جديد مربوط بهذا الجهاز، فيتحوّل التطبيق عند العميل من التجربة إلى الترخيص عند
  أول تحقق (أو عندما يضغط «تحقّق الآن»)، وأرسل له الكود ليحتفظ به.
- **إعدادات:** السعر الظاهر، رقم واتساب لزر «اشترِ عبر واتساب»، أيام التجربة، أيام السماح، أقل إصدار، بصمة توقيع أندرويد، ورسالة تظهر في
  شاشة التفعيل. وفي الأسفل عنوان الخادم والمفتاح العام لمن يبني التطبيق.

## كيف يعمل الترخيص (باختصار)

- **رمز الجهاز** (مثل `K7M2-QX9P`) يظهر عند العميل في شاشة التفعيل. يرسله لك عند الشراء؛ به تجد جهازه في تبويب الأجهزة.
- **الكود** (مثل `ABCD-EFGH-JKLM`) يُدخله العميل مرة واحدة وهو متصل بالإنترنت، فيرتبط بجهازه. يعمل بعدها بلا إنترنت.
- **التجربة:** تجربة مجانية واحدة لكل جهاز، مدتها «أيام التجربة» من الإعدادات (الافتراضي 7، و0 يوقفها). لا تتكرر على الجهاز نفسه أبداً.
- **أيام السماح:** يتحقق التطبيق من الخادم كل ست ساعات عندما يجد إنترنت. إن بقي بلا تحقق أكثر من «أيام السماح» (الافتراضي 10) يتوقف حتى يتصل
  ويتحقق مرة. هذا ما يجعل الإلغاء ونقل الترخيص نافذين حتى على جهاز يعمل بلا إنترنت معظم الوقت. لا تجعلها قصيرة جداً (أسبوع على الأقل).
- **نقل الترخيص إلى جهاز جديد:** إما من التطبيق (شاشة التفعيل ← «نقل الترخيص لجهاز آخر»، حتى 3 مرات)، أو من عندك (بطاقة الكود ← تحرير
  جهاز، بلا حدود). ثم يُدخل العميل الكود نفسه على الجهاز الجديد.
- **الإلغاء:** من بطاقة الكود. يتوقف التطبيق عند العميل عند أول تحقق. «إعادة الكود» تعيده.
- **أقل إصدار:** اكتب مثلاً `1.2.0` لتُطالب النسخ الأقدم بالتحديث (لا تُفعَّل ولا تجتاز التحقق). اتركه فارغاً في العادة.
- **بصمة توقيع أندرويد:** إن كتبت فيها بصمة شهادة التوقيع (SHA-256) الخاصة بنسخة أندرويد الأصلية، يرفض الخادم أي نسخة أندرويد أعيد توقيعها
  (تطبيق معدّل). تجد بصمة أي جهاز أندرويد في بطاقته بتبويب الأجهزة. فارغة = لا تحقق.
- لا يمكن لأحد تزوير ترخيص: كل ترخيص موقّع بمفتاح لا يوجد إلا على الخادم، والتطبيق لا يقبل إلا توقيع هذا المفتاح.

## حل المشاكل

- **«لم يُضبط الخادم بعد» أو المفتاح العام فارغ:** السر `KASEB_LICENSE_SECRET` غير مضاف. أضفه ثم شغّل Deploy Kaseb server من جديد.
- **العميل يرى «الكود غير صحيح»:** تأكد أنه يكتبه كاملاً (12 حرفاً)، وأن الكود من هذا الخادم لا من خادم آخر، وأنه غير ملغى.
- **«هذا الكود مستخدم على جهاز آخر»:** الكود مربوط بجهاز آخر. حرّر الجهاز القديم من بطاقة الكود، أو زد عدد الأجهزة المسموح.
- **«بحاجة إلى اتصال بالإنترنت» عند العميل:** مرّت أيام السماح بلا تحقق، أو غُيّر وقت الجهاز إلى الوراء. يكفي اتصال واحد وضغطة «تحقّق الآن».
- **«نسخة معدّلة من التطبيق»:** بصمة أندرويد لا تطابق المسموح في الإعدادات. راجع البصمة في بطاقة الجهاز، أو أفرغ الحقل.
- **«محاولات كثيرة»:** أكثر من 30 محاولة تفعيل من العنوان نفسه خلال 10 دقائق. انتظر قليلاً.
- **نسيت مفتاح الإدارة:** غيّر السر `KASEB_ADMIN_KEY` في GitHub وشغّل سير النشر من جديد.
- **تغيّر عنوان الخادم:** التطبيق مبني على العنوان القديم، فيجب إعادة بناء التطبيق بالعنوان الجديد (متغير `KASEB_API`).
- **سياسة الخصوصية** (لمتجر Google Play): `https://kaseb-api.<اسمك>.workers.dev/privacy`.

## للمطوّر

```
cd pos/server && npm install
printf "LICENSE_SECRET=dev\nADMIN_KEY=dev\n" > .dev.vars
npm run db:local                      # creates the local D1 from schema.sql
npm run dev                           # http://localhost:8787  (/admin with the key "dev")
npm run check                         # tsc --noEmit
```
Then build the app against it: `POS_API=http://localhost:8787 POS_LICENSE_PUBLIC_KEY=<from /api/public-key> npx vite build`.

API (JSON, CORS `*`, errors `{ error, message }` with 400/403/429): `GET /api/info`, `GET /api/public-key`, `POST /api/activate`,
`POST /api/trial`, `POST /api/check`, `POST /api/release`; the panel's API under `/admin/api/*` with `Authorization: Bearer <ADMIN_KEY>`.
Tables: `codes`, `devices`, `events`, `settings` (schema.sql). The full contract is in `pos/docs/LICENSE-SPEC.md`.
