# Research: platform-behaviour

_Read from primary sources on 2026-11-13 and re-checked by an independent second pass._

## Summary

Re-checked every claim on 2026-11-13 against the live pages, Chromium/AOSP source, Google Maven and the SDK index. Nothing was device-tested.

**Confirmed:** Play requires target API 36 for new apps (since 31 Aug 2026; the 1 Nov extension has lapsed). API 37 is stable in the SDK but optional. Edge-to-edge, predictive back and large-screen rules are as stated. The game exemption is real: AOSP checks ApplicationInfo.CATEGORY_GAME in Android 16 and 17. WebViewAssetLoader without INTERNET: yes by source reading in M51 and main; no upstream test covers that combination.

**Corrected:**
- MIME lookup order was inverted: the OS table is consulted first, then the hardcoded table, then text/plain.
- android:isGame is deprecated since API 26.
- AudioContext on old WebViews is now checked: not gesture-gated in the main frame at M51–M53, M55, M58, M66, M74 or main.
- viewport-fit=cover is not gated in main-branch code; include it anyway.

**Missed, and build-affecting:**
- androidx.core 1.19.x requires compileSdk 37 and AGP 9.1.0+; with compileSdk 36 use core 1.18.0.
- androidx.webkit 1.18.0 forces minSdk 24.
- WebView scales HTML text by the system font scale unless setTextZoom(100) is called.
- navigator.vibrate() is a silent no-op without the VIBRATE permission.
- Google Play accepts only App Bundles (.aab) for new apps, not an APK.
- data-extraction-rules gained a cross-platform-transfer section.

## Facts

- **Google Play target API requirement in force on 2026-11-13** — "Starting August 31, 2026: New apps and app updates must target Android 16 (API level 36) or higher" (Wear OS and Automotive: 35; TV and XR: 34). Extension requests ran only until 1 Nov 2026, so it has lapsed. Existing apps must target 35+ to stay available to new users on newer devices. The page does not mention API 37.  
  Source: https://support.google.com/googleplay/android-developer/answer/11926878 (verified-primary-source)
- **Planned date for an API 37 Play requirement** — The Jan 2025 Android blog post states the plan: "targeting API 36 will be required in August 2026" and "targeting API 37 will be required in August 2027". It is a stated plan, not a policy in force.  
  Source: https://android-developers.googleblog.com/2025/01/orientation-and-resizability-changes-in-android-16.html (verified-primary-source)
- **Android 17 / API 37 SDK status** — repository2-3.xml lists platforms;android-37.0 (rev 2, api-level 37.0, no codename), android-37.1, android-37.2 (rev 2) and build-tools;37.0.0 (non-preview revision). Newest build-tools is 37.0.0; newest API 36 platform is android-36.1. The AOSP tag android-17.0.0_r1 exists. Beta and canary packages also carry channel-0, so the empty codename, not the channel, is what marks 37.0 as final.  
  Source: https://dl.google.com/android/repository/repository2-3.xml (verified-primary-source)
- **Android 17 public release date** — The release-notes page lists only betas, the last being Beta 4.1 (1 Jun 2026). Press coverage puts the stable Pixel rollout at 16 Jun 2026. No Google primary page with the date was found.  
  Source: https://developer.android.com/about/versions/17/release-notes (secondary-source)

- **Google Play accepts only App Bundles for new apps** — "From August 2021, new apps are required to publish with the Android App Bundle on Google Play." A signed APK cannot be uploaded as a new app's release; the deliverable for Play is an .aab.  
  Source: https://developer.android.com/guide/app-bundle (verified-primary-source)
- **Target 36: edge-to-edge opt-out removed** — For apps targeting API 36, R.attr#windowOptOutEdgeToEdgeEnforcement is deprecated and disabled on Android 16 devices; it still works on an Android 15 device.  
  Source: https://developer.android.com/about/versions/16/behavior-changes-16 (verified-primary-source)
- **Target 35+: what edge-to-edge enforcement changes on Android 15+** — Status bar and gesture nav bar are transparent. 3-button nav gets an 80% opaque background (navigationBarContrastEnforced true by default). Content draws behind bars unless insets are applied. setStatusBarColor has no effect. layoutInDisplayCutoutMode of non-floating windows must be ALWAYS (SHORT_EDGES, NEVER and DEFAULT are interpreted as ALWAYS). If the app crashes on launch because of the splash screen, upgrade core-splashscreen to 1.2.0-alpha01 or later, or set the cutout mode to always.  
  Source: https://developer.android.com/about/versions/15/behavior-changes-15 (verified-primary-source)
- **Target 36: predictive back** — On Android 16+ devices the predictive back system animations are on by default, "onBackPressed is not called and KeyEvent.KEYCODE_BACK is not dispatched anymore". Temporary opt-out: android:enableOnBackInvokedCallback="false" on <application> or <activity>.  
  Source: https://developer.android.com/about/versions/16/behavior-changes-16 (verified-primary-source)
- **OnBackPressedCallback under predictive back** — "OnBackPressedCallback is always called regardless of the value of android:enableOnBackInvokedCallback." It needs AndroidX Activity 1.6.0+, so the activity must extend ComponentActivity; a plain android.app.Activity has to use the platform OnBackInvokedCallback API instead. This comes from the predictive-back guide, not the behaviour-changes page the first pass cited.  
  Source: https://developer.android.com/guide/navigation/custom-back/predictive-back-gesture (verified-primary-source)
- **Target 36: orientation, resizability and aspect-ratio restrictions ignored on large screens** — On displays with smallest width >= 600dp, screenOrientation (portrait/landscape and their reverse, sensor and user variants), resizeableActivity=false, minAspectRatio, maxAspectRatio and setRequestedOrientation() are ignored. Exceptions: "Games (based on the android:appCategory flag)", users opting in via aspect-ratio settings, and screens smaller than sw600dp. Temporary opt-out property: android.window.PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY = true.  
  Source: https://developer.android.com/about/versions/16/behavior-changes-16 (verified-primary-source)
- **Target 37: opt-out removed, games exemption kept** — "Android 17 removes the temporary developer opt-out" for apps targeting API 37. The exceptions list still starts with "Games (based on the android:appCategory flag)".  
  Source: https://developer.android.com/about/versions/17/changes/ff-restrictions-ignored (verified-primary-source)

- **Display compatibility mode for games** — "Display compatibility mode mode is enabled by default for games (based on the android:appCategory flag)"; the app still receives onConfigurationChanged but is spared a restart when moving between displays.  
  Source: https://developer.android.com/guide/practices/device-compatibility-mode (verified-primary-source)
- **Other Android 17 changes that could touch this app** — All apps on Android 17: background audio playback and volume calls made outside a valid lifecycle fail silently and audio-focus requests return AUDIOFOCUS_REQUEST_FAILED; new per-app memory limits (exit description "MemoryLimiter:AnonSwap"). Target 37 only: stricter background audio (foreground service required), static final fields unmodifiable by reflection, lock-free MessageQueue, CT on by default, ECH, ACCESS_LOCAL_NETWORK.   Source: https://developer.android.com/about/versions/17/behavior-changes-all (verified-primary-source)

Starting February 1, 2027, if your app updates don't support 16 KB memory page sizes, you won't be able to release these updates." Apps with only Java/Kotlin code already comply. The AARs for core 1.19.1, core-ktx 1.19.1, webkit 1.18.0, core-splashscreen 1.2.0, activity 1.13.0 and the transitive profileinstaller, tracing, startup, navigationevent, lifecycle-runtime, savedstate and appcompat-resources contain no .so files (each AAR listed).  
  Source: https://developer.android.com/guide/practices/page-sizes (verified-primary-source)
- **Immersive fullscreen API** — WindowCompat.getInsetsController(window, window.decorView), then systemBarsBehavior = BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE and hide(WindowInsetsCompat.Type.systemBars()). Transient bars overlay content and auto-hide. In desktop windowing the caption bar is always visible, even for immersive games, so use Type.systemBars() or Type.captionBar() insets to keep UI clear of it.  
  Source: https://developer.android.com/develop/ui/views/layout/immersive (verified-primary-source)
- **Edge-to-edge on pre-Android-15 devices** — Call WindowCompat.enableEdgeToEdge(window) in onCreate after super.onCreate. The reference marks it "Added in 1.17.0" of androidx.core. Bars become transparent except a translucent scrim in 3-button mode; set window.isNavigationBarContrastEnforced = false to remove the scrim.  
  Source: https://developer.android.com/reference/androidx/core/view/WindowCompat (verified-primary-source)
- **Display cutout modes and API levels** — layoutInDisplayCutoutMode, DEFAULT, SHORT_EDGES and NEVER were added in API 28; LAYOUT_IN_DISPLAY_CUTOUT_MODE_ALWAYS in API 30. The cutout guide says to use always, shortEdges or never if the app moves in and out of immersive mode, because the default mode renders into the cutout only while bars are present. The window never extends into long-edge cutouts in SHORT_EDGES mode.  
  Source: https://developer.android.com/reference/android/view/WindowManager.LayoutParams (verified-primary-source)
- **Re-hiding system bars after focus loss** — Re-applying hide(systemBars()) in onWindowFocusChanged(true) is common practice for API < 30; no current Google page states it. It is harmless to do.  
  Source: https://developer.android.com/develop/ui/views/layout/immersive (unverified)
- **WebViewAssetLoader without INTERNET: are shouldInterceptRequest responses delivered for https URLs? (current WebView)** — YES by source reading. InterceptedRequest::Restart() returns ERR_ACCESS_DENIED only if ShouldBlockURL() is true. ContinueRestartAfterCustomHeaders() then applies UpdateLoadFlags() and still calls ShouldInterceptRequestAsync. A non-null response goes to ContinueAfterInterceptWithOverride and AndroidStreamReaderURLLoader, which uses neither cache nor network. Only un-intercepted requests continue to the network factory with cache-only flags. Not device-tested; Chromium's AwSettingsTest has no test combining setBlockNetworkLoads(true) with interception.  
  Source: https://chromium.googlesource.com/chromium/src/+/refs/heads/main/android_webview/browser/network_service/aw_proxying_url_loader_factory.cc (verified-primary-source)
- **Definitions of ShouldBlockURL and UpdateLoadFlags** — UpdateLoadFlags: under ShouldBlockNetworkLoads() it sets LOAD_ONLY_FROM_CACHE | LOAD_SKIP_CACHE_VALIDATION. ShouldBlockURL ends with `return client->ShouldBlockNetworkLoads() && url.SchemeIs(url::kFtpScheme);`. It blocks content:// and file:// per settings, never http(s). file:///android_asset and android_res URLs are "always available" even with file access off.  
  Source: https://chromium.googlesource.com/chromium/src/+/refs/heads/main/android_webview/browser/network_service/net_helpers.cc (verified-primary-source)
- **Same behaviour in the oldest WebView the app can meet (M51)** — M51: `if (io_client->ShouldBlockNetworkLoads()) { if (request_->url().SchemeIs(url::kFtpScheme)) return true; SetCacheControlFlag(request_, net::LOAD_ONLY_FROM_CACHE); }`. Interception is a separate net::URLRequestInterceptor (AwRequestInterceptor, registered in aw_url_request_context_getter.cc) that builds an AndroidStreamReaderURLRequestJob, so it is not gated by this flag.  
  Source: https://chromium.googlesource.com/chromium/src/+/refs/tags/51.0.2704.91/android_webview/browser/renderer_host/aw_resource_dispatcher_host_delegate.cc (verified-primary-source)

WebSettings doc: default is false with INTERNET, otherwise true.  
  Source: https://chromium.googlesource.com/chromium/src/+/refs/heads/main/android_webview/java/src/org/chromium/android_webview/AwSettings.java (verified-primary-source)
- **Android docs on in-app content** — "In-app content doesn't require internet access or consume a user's bandwidth."   Source: https://developer.android.com/develop/ui/views/layout/webapps/load-local-content (verified-primary-source)

  Source: https://developer.android.com/identity/data/autobackup (verified-primary-source)
- **androidx.core adds a self-defined permission to the merged manifest** — core 1.19.1's manifest declares <permission android:name="${applicationId}.DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION" android:protectionLevel="signature"/> and a matching <uses-permission> (also present in 1.16–1.18). ContextCompat.registerReceiver(..., RECEIVER_NOT_EXPORTED) on API < 33 throws RuntimeException("Permission ... is required by your application to receive broadcasts") if it is missing, so removing it is safe only if nothing makes that call.  
  Source: https://android.googlesource.com/platform/frameworks/support/+/refs/heads/androidx-main/core/core/src/main/java/androidx/core/content/ContextCompat.java (verified-primary-source)
- **android:appCategory and android:isGame** — appCategory values: accessibility, audio, game, image, maps, news, productivity, social, video; game = "Apps that are primarily games". android:isGame is deprecated as of Android 8.0 (API 26): "Use the appCategory attribute set to game instead."  
  Source: https://developer.android.com/guide/topics/manifest/application-element (verified-primary-source)
- **supportsRtl, hardwareAccelerated, resizeableActivity, cleartext** — supportsRtl defaults to false. hardwareAccelerated defaults to true when min or target SDK >= 14. resizeableActivity defaults to true for target >= 24; on sw < 600dp, false means no multi-window; on sw >= 600dp it is ignored for target 36. usesCleartextTraffic defaults to false for target >= 28 and "is getting deprecated and will be ignored for apps targeting API levels 38 and above".  
  Source: https://developer.android.com/guide/topics/manifest/application-element (verified-primary-source)
- **android:configChanges values** — Valid values: colorMode, density (API 24), fontScale, fontWeightAdjustment, grammaticalGender (API 34), keyboard, keyboardHidden, layoutDirection, locale, mcc, mnc, navigation, orientation, screenLayout, screenSize, smallestScreenSize, touchscreen, uiMode. A declared value stops the restart and calls onConfigurationChanged. With orientation also declare screenSize and screenLayout; for multi-window use screenLayout and smallestScreenSize.  
  Source: https://developer.android.com/guide/topics/manifest/activity-element (verified-primary-source)
- **Per-app languages (localeConfig)** — res/xml/locale_config.xml with <locale-config xmlns:android="http://schemas.android.com/apk/res/android"><locale android:name="en"/><locale android:name="ar"/></locale-config> and android:localeConfig="@xml/locale_config" on <application>; effective in system settings on Android 13+. Alternative: androidResources { generateLocaleConfig = true }; the build fails if a manual file also exists. Below API 33, per-app language needs AppCompat 1.6+ or an in-app picker.  
  Source: https://developer.android.com/guide/topics/resources/app-languages (verified-primary-source)

## Action items

- Set targetSdk = 36 (37 is also accepted). Choose the compileSdk and androidx.core pair deliberately: compileSdk 37 with AGP 9.1.1+ and core 1.19.1, or compileSdk 36 with AGP 8.9.1+ and core 1.18.0. Mixing compileSdk 36 with core 1.19.x fails the AAR metadata check.
- Set minSdk = 24; androidx.webkit 1.18.0 will not merge below that.
- Produce a signed Android App Bundle (.aab) for the Play upload. An APK can be built as well for sideload testing, but Play will not accept it as a new app's release.
- Declare android:appCategory="game" on <application> so the portrait lock keeps working on tablets and foldables under target 36 and 37. Do not use android:isGame.
- Handle back with OnBackPressedCallback on a ComponentActivity (androidx.activity 1.13.0). Do not rely on onBackPressed or KEYCODE_BACK.
- Load the game only from https://appassets.androidplatform.net/assets/... through WebViewAssetLoader and WebViewClientCompat.shouldInterceptRequest. Never call setBlockNetworkLoads(false). Reference no external URL anywhere in the HTML, CSS or JS.
- Before submission, run the release build on an emulator at API 24 and at API 36 with no INTERNET permission and confirm the page, scripts, images, audio and fonts all load. This is the one behaviour confirmed only by reading source.
- WebView settings: javaScriptEnabled = true, domStorageEnabled = true only if the page needs it, allowFileAccess = false, allowContentAccess = false, textZoom = 100, mediaPlaybackRequiresUserGesture = false. Also resume the AudioContext on the first touch as a second line of defence.
- Block every navigation away from the appassets origin in shouldOverrideUrlLoading, and expose the JS bridge only to that page. This keeps the app clear of Play's JavaScript Interface Injection check.
- Save progress through the JS bridge into SharedPreferences, not localStorage, because localStorage commits to disk at least 5 seconds late. Bridge methods run on a background thread, so keep them thread-safe and post UI work to the main thread.
- In Activity.onPause call webView.onPause() (and pauseTimers()); in onResume call onResume() (and resumeTimers()). In JS, suspend the AudioContext and stop the game loop on visibilitychange.
- Call WindowCompat.enableEdgeToEdge(window) after super.onCreate, then hide systemBars() with BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE, and re-apply the hide in onWindowFocusChanged(true).
- Set android:windowLayoutInDisplayCutoutMode to shortEdges in values-v28 and always in values-v30 so the layout does not jump on Android 9–14.
- Do not depend on CSS env(safe-area-inset-*) alone: it is 0 before WebView 86 and below API 28, cutout-only until M135, and fullscreen-only until M144. Read the display-cutout and system-bar insets natively and pass them to the page as CSS variables. Attach the insets listener to the root view, not to the WebView, so WebView's own listener on Android 9–11 is not replaced. Keep viewport-fit=cover in the viewport meta tag.
- Ship the JS as one classic script at ES2015 level with no ES modules, async/await, optional chaining, PointerEvent-only input, CSS grid, flex gap, aspect-ratio or min()/max(), or detect missing features at start-up and show an 'update Android System WebView' screen. A never-updated Android 7.0 device has WebView 51.
- Implement onRenderProcessGone: return true, remove and destroy the WebView, create a new one and reload from the saved state.
- Declare android:configChanges for orientation, screenSize, screenLayout, smallestScreenSize, density, keyboard, keyboardHidden, navigation, uiMode, fontScale, locale and layoutDirection so the WebView is not recreated, and still persist state so an unavoidable recreation is survivable.
- Add both backup rule files with include-only rules for the save SharedPreferences file (cloud-backup and device-transfer sections, plus full-backup-content for Android 11 and lower) and set allowBackup, fullBackupContent and dataExtractionRules explicitly.
- For haptics call View.performHapticFeedback through the bridge; navigator.vibrate() does nothing without the VIBRATE permission.
- Decide on the androidx.core DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION entry: either leave it (signature-level, not user-facing) or strip both the <permission> and <uses-permission> with tools:node="remove", and then never call ContextCompat.registerReceiver with RECEIVER_NOT_EXPORTED.
- Optionally add the WebView manifest meta-data android.webkit.WebView.MetricsOptOut=true and android.webkit.WebView.EnableSafeBrowsing=false, since the app only ever loads bundled content.
- Set android:supportsRtl="true" and add locale_config.xml (or generateLocaleConfig) if the app ships Arabic alongside English.
- After building, list the bundle or APK and confirm there is no lib/ directory or .so file, which keeps the 16 KB requirement satisfied.
