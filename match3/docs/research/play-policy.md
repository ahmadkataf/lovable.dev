# Research: play-policy

_Read from primary sources on 2026-11-13 and re-checked by an independent second pass._

## Summary

I re-opened every cited page on 2026-11-13 and nearly all findings hold. Three were wrong or unsupported, and I added several the first pass missed.

Confirmed: new apps must target API 36 (extension ended Nov 1, 2026; API 37 in August 2027). New apps must upload a signed .aab under Play App Signing, so an APK cannot be the Play deliverable. A privacy policy URL plus in-app link or text is mandatory. Personal accounts created after Nov 13, 2023 need 12 testers for 14 continuous days, so first-day production release is impossible for them.

Corrected:
- The "July 2026 … we don't allow unrated apps" quote is not on the cited page. The policy reads "We don't allow apps without a content rating on Google Play."
- The "standard declarations" list quote, including an Advertising ID declaration, is on no Google page I could open; that declaration rests on third-party sources.
- Size limits were cited to the wrong page; the base module limit is 500 MB.

Added:
- Without INTERNET, WebView defaults to blocking network loads, but bundled assets and WebViewAssetLoader still work (Android docs and Chromium source).
- androidx.core 1.19.1 merges a signature-level custom permission, so "zero permissions" needs an explicit manifest removal.
- WebView uploads consented diagnostics unless the manifest opts out.
- The policy in force is dated October 29, 2026; the listing may not compare the game to other games.
- Free games appear on Google Play Games on PC by default.

No source guarantees first-pass approval.

## Facts

- **Target API level required for new apps and updates today (2026-11-13)** — CONFIRMED. "Starting August 31, 2026: New apps and app updates must target Android 16 (API level 36) or higher to be submitted to Google Play" (Wear OS and Automotive: API 35; TV and XR: API 34). "When you publish a new app, you must target Android 16 (API level 36) or higher." The only extension ran "to November 1, 2026", which has passed, so targetSdk 36 is the hard floor.  
  Source: https://support.google.com/googleplay/android-developer/answer/11926878?hl=en (verified-primary-source)
- **Underlying target API policy rule** — CONFIRMED. "New apps and app updates MUST target an Android API level within one year of the latest major Android version release. New apps and app updates that fail to meet this requirement will be prevented from app submission in Play Console."  
  Source: https://support.google.com/googleplay/android-developer/answer/16561298?hl=en (verified-primary-source)
- **Next target API deadline** — CONFIRMED. "For Google Play, new apps and updates will be required to target API level 37, making this behavior mandatory for distribution in August 2027." No exact day is given, and the Play target-API help page does not mention API 37 yet.  
  Source: https://android-developers.googleblog.com/2026/02/prepare-your-app-for-resizability-and.html (verified-primary-source)
- **SDK platform and build-tools packages for API 36 and 37 exist as stable releases** — CONFIRMED from repository metadata. Stable channel (channel-0) contains platforms;android-36 (rev 2), platforms;android-36.1, platforms;android-37.0 (rev 2), platforms;android-37.1 and platforms;android-37.2. Stable build-tools: 36.0.0, 36.1.0, 37.0.0. Note the API 37 package path is "platforms;android-37.0", not "android-37". The Android 17 setup page shows compileSdk = 37 / targetSdk = 37 and requires AGP 8.9.0-rc01 or higher.  
  Source: https://dl.google.com/android/repository/repository2-3.xml (verified-primary-source)
- **Android App Bundle is mandatory for new apps; APK is legacy-only** — CONFIRMED. "Important: From August 2021, new apps are required to publish with the Android App Bundle on Google Play." Play Console Help: "Releases allow Android developers to manage Android App Bundles (or APKs for apps created before August 2021)" and "Note: Legacy apps (created before August 2021) can use app bundles or APKs in releases." A new app cannot ship an APK to Play.  
  Source: https://developer.android.com/guide/app-bundle (verified-primary-source)
- **Release form details** — CONFIRMED. Release notes: "up to 500 Unicode characters per language." "Rollout percentage options are unavailable for a first release." A first production rollout "publishes your app to all Google Play users in your selected countries or regions."  
  Source: https://support.google.com/googleplay/android-developer/answer/9859348?hl=en (verified-primary-source)
- **Play App Signing and the upload key** — CONFIRMED. Upload key: "Stored in a Java keystore (.jks or .keystore)", "Must be an RSA key of 2048 bits or more", "You use this key to sign your app bundle before uploading it to the Play Console... If compromised or lost, Google can reset it for you." App signing key: Google "uses this key to sign the final APKs delivered to users' devices"; Google-generated keys are RSA 4096-bit. New apps are "automatically enrolled in quantum-ready, hybrid signing with Google-generated keys" (not compatible with v4 signing). Creating an app requires you to "Accept the Play App Signing Terms of Service."  
  Source: https://support.google.com/googleplay/android-developer/answer/9842756?hl=en (verified-primary-source)
- **versionCode limit** — CONFIRMED. "the maximum possible value for the versionCode is 2100000000"; "you must increase the versionCode for every update."  
  Source: https://support.google.com/googleplay/android-developer/answer/9859152?hl=en (verified-primary-source)
- **Size limits (CORRECTED source and detail)** — The original finding cited the wrong page (9859152 only links out). The actual limits by compressed download size: base module 500 MB; individual feature modules 500 MB; individual asset packs 1.5 GB; cumulative total for all modules and install-time asset packs 4 GB. "Apps still publishing with APKs instead of app bundles are subject to legacy APK size limits (that is, a maximum APK size of 100MB)." Above 200 MB, users on mobile data see a non-blocking dialog.  
  Source: https://support.google.com/googleplay/android-developer/answer/9859372?hl=en (verified-primary-source)
- **Store listing text limits and contact email** — CONFIRMED. App name 30 characters; short description 80; full description 4,000. "A contact email address is required." "Repetitive or irrelevant keyword usage in your app name, short description, or full description can create an unpleasant user experience and result in app suspension."  
  Source: https://support.google.com/googleplay/android-developer/answer/9859152?hl=en (verified-primary-source)
- **Free games are distributed on Google Play Games on PC by default (MISSED by first pass)** — "Note: If your game is free, it appears on both Google Play and Google Play Games on PC by default. If your game is paid, you must release it on Google Play Games on PC yourself." The PC playability checklist requires the game to be "playable on PCs with a mouse and keyboard" (compatibility mode is sufficient) and not blocked by unsupported permissions or features.  
  Source: https://support.google.com/googleplay/android-developer/answer/9859152?hl=en (verified-primary-source)
- **App icon spec for the store listing** — CONFIRMED. "32-bit PNG (with alpha)", "Dimensions: 512px by 512px", "Maximum file size: 1024KB". Design spec: sRGB, "Shape: Full square – Google Play dynamically handles masking. Radius will be equivalent to 30% of icon size", "Shadow: None"; "Don't add drop shadows to your final asset"; "Don't use text or graphic elements to indicate ranking".  
  Source: https://developer.android.com/distribute/google-play/resources/icon-design-specifications (verified-primary-source)
- **Feature graphic spec** — CONFIRMED. "You must provide a feature graphic to publish your store listing." "JPEG or 24-bit PNG (no alpha)", "Dimensions: 1024px by 500px". Recommended: keep the focal point centred, avoid pure white, black or dark gray, no "Best", "#1", "Top", "New", "Free", "Discount", "Sale", "Million Downloads", no device imagery, no store badges, no third-party trademarked characters or logos without permission.  
  Source: https://support.google.com/googleplay/android-developer/answer/9866151?hl=en (verified-primary-source)
- **Screenshot requirements** — CONFIRMED. "You must provide a minimum of two screenshots across different device types to publish your store listing": JPEG or 24-bit PNG (no alpha), minimum dimension 320px, maximum 3840px, "The maximum dimension of your screenshot can't be more than twice as long as the minimum dimension." Up to 8 per device type. For games to be eligible for large-format recommendations: "at least three 16:9 landscape screenshots (minimum 1920x1080px) or three 9:16 portrait screenshots (minimum 1080x1920px)" showing the in-game experience. Tablet and Chromebook sets are optional: minimum 4 if provided, 1,080 to 7,680px, 16:9 or 9:16.  
  Source: https://support.google.com/googleplay/android-developer/answer/9866151?hl=en (verified-primary-source)
- **Screenshot and short-description content rules** — CONFIRMED. Use captured footage of the game itself; taglines "should not take up more than 20% of the image"; no "Best", "#1", "Top", "New", "Discount", "Sale", "Million Downloads"; no calls to action ("Download now", "Play now"); no device imagery or fingers; full battery, WiFi and signal icons with no notifications; alt text "140 characters or less". Short description: no emojis, emoticons, repeated punctuation, star symbols, or capitalization for emphasis.  
  Source: https://support.google.com/googleplay/android-developer/answer/9866151?hl=en (verified-primary-source)
- **Metadata policy for title, icon and developer name** — CONFIRMED. "Don't use emojis, emoticons, or repeated special characters in these metadata elements. Avoid ALL CAPS unless it is part of your brand name... Your app title must be 30 characters or less. Don't use text or image in the app title, icon, or developer name that indicate store performance or ranking, price or promotional information, or that suggests relations to existing Google Play programs." Also prohibited: unattributed or anonymous user testimonials, word blocks, misleading symbols in icons, claims like "best game ever".  
  Source: https://support.google.com/googleplay/android-developer/answer/9898842?hl=en (verified-primary-source)
- **Store listing must not compare the game to other games (STRENGTHENED)** — CONFIRMED and extended. "Words like 'Free' and 'No Ads' promote deals and don't belong in app titles or developer names." "Saying that something is the 'best' or '#1 rated' or comparing it to another app isn't permitted." "Don't include misleading or irrelevant references to other apps, products, or people. Also, don't compare your app or game to other apps or games." "Don't repeat your short description in your full description." So the listing must not say anything like "like Candy Crush".  
  Source: https://support.google.com/googleplay/android-developer/answer/13393723?hl=en (verified-primary-source)
- **Privacy policy is required for every app, even with no data collection** — CONFIRMED. "You must link to a privacy policy on your store listing and within your app, even if your app doesn't access personal or sensitive user data or target children." The URL must be active, public, http(s) with a valid SSL certificate, not geofenced, no login, "displayed on a standard, non-editable webpage (not a PDF or downloadable file)", and apply specifically to your app.  
  Source: https://support.google.com/googleplay/android-developer/answer/9859455?hl=en (verified-primary-source)
- **Required privacy policy contents; in-app text is acceptable** — CONFIRMED. "All apps must post a privacy policy link in the designated field within Play Console, and a privacy policy link or text within the app itself." Must include developer information and a privacy point of contact, data types accessed/collected/used/shared, secure data handling procedures, retention and deletion policy, and "Clear labeling as a privacy policy". "The entity ... named in the app's Google Play store listing must appear in the privacy policy or the app must be named in the privacy policy. Apps that do not access any personal and sensitive user data must still submit a privacy policy." Because in-app text is allowed, an app with no INTERNET permission can satisfy the in-app half with a bundled screen.  
  Source: https://support.google.com/googleplay/android-developer/answer/10144311?hl=en (verified-primary-source)
- **Data safety form for an app that collects and shares nothing** — CONFIRMED. "Even developers with apps that do not collect any user data must complete this form and provide a link to their privacy policy." "If your app collects or shares any of the required user data types, select Yes. If not, select No." "'Collect' means transmitting data from your app off a user's device." "User data accessed by your app that is only processed locally on the user's device and not sent off device does not need to be disclosed." Required for closed, open and production tracks; internal testing is exempt.  
  Source: https://support.google.com/googleplay/android-developer/answer/10787469?hl=en (verified-primary-source)
- **Content rating is mandatory (CORRECTED quote)** — The original quote "July 2026 clarification: we don't allow unrated apps on Google Play" is NOT on the cited page and no July 2026 attribution was found. Actual policy text: "We don't allow apps without a content rating on Google Play." and "Apps without a content rating will be removed from the Play Store." "Misrepresentation of your app's content may result in removal or suspension." The questionnaire steps (enter email for IARC, select a category, complete, submit) are confirmed on answer/9859655; "Unrated apps may be removed from Google Play" is on answer/9859455.  
  Source: https://support.google.com/googleplay/android-developer/answer/9898843?hl=en (verified-primary-source)
- **Target audience: children versus 13+** — CONFIRMED. "Any apps that have at least one target audience age group that includes children must comply with Google Play's Families Policy Requirements." Ages 5 and under, 6-8 and 9-12 are "considered to include children in most locales"; 13-15 and 16-17 "may be considered to include children in some locales". Privacy policy, ads declaration and app access must be completed first. Extended reviews may take "up to 7 days or longer in exceptional cases".  
  Source: https://support.google.com/googleplay/android-developer/answer/9867159?hl=en (verified-primary-source)
- **Unintentional appeal to children (wording CORRECTED)** — "If your app is not primarily designed for children under 13 but your listing contains marketing elements that suggest otherwise (such as youthful animation or young characters in the graphic assets), Google Play may reject your app." The two options given are: remove the child-appealing marketing elements, or "Change the target age group(s) of your app to only include children under 13 (which will require complying with Google Play Families Policy)". The best-practices page adds: "you may declare child age groups in your target audience or remove those elements." A bright candy-style match-3 is exposed to this.  
  Source: https://support.google.com/googleplay/android-developer/answer/9867159?hl=en (verified-primary-source)
- **Families Policy requirements if children are in the target audience** — CONFIRMED. "Your app must not merely provide a webview of a website or have a primary purpose of driving affiliate traffic to a website without permission from the website owner or administrator." Apps solely targeting children must not transmit AAID, SIM Serial, Build Serial, BSSID, MAC, SSID, IMEI or IMSI, may not request location permission, and must not contain APIs or SDKs not approved for child-directed services. Must comply with COPPA and GDPR. "if you choose to include imagery and terminology in your app that could be considered targeting children, this may impact Google Play's assessment of your declared target audience." An offline, zero-permission, no-SDK game meets the technical parts.  
  Source: https://support.google.com/googleplay/android-developer/answer/9893335?hl=en (verified-primary-source)
- **Closed-testing requirement for new personal developer accounts** — CONFIRMED. "Developers with personal accounts created after November 13, 2023, must run a closed test for their app with a minimum of 12 testers who have been opted in continuously for at least 14 days." Production and Pre-registration remain disabled until then. The production application has three sections (closed test, app/game, production readiness). "Review usually takes seven days or less, but can occasionally take longer." "If a tester opts out and opts back in later, the 14 days must be consecutive." Open testing becomes available only after production access. The build cannot bypass this.  
  Source: https://support.google.com/googleplay/android-developer/answer/14151465?hl=en (verified-primary-source)

  Source: https://support.google.com/googleplay/android-developer/answer/14316361?hl=en (verified-primary-source)

- **Behaviour changes forced by targeting API 36** — CONFIRMED (page last updated 2026-10-28). (a) Edge-to-edge: windowOptOutEdgeToEdgeEnforcement "is deprecated and disabled, and your app can't opt-out of going edge-to-edge." (b) Predictive back: on Android 16+ devices "onBackPressed is not called and KeyEvent.KEYCODE_BACK is not dispatched anymore"; migrate to supported back APIs or "temporarily opt out by setting the android:enableOnBackInvokedCallback attribute to false". (c) On displays with smallest width >= 600dp, screenOrientation, resizeableActivity, minAspectRatio and maxAspectRatio are ignored. Exceptions: "Games (based on the android:appCategory flag)" and "Screens that are smaller than sw600dp". The PROPERTY_COMPAT_ALLOW_RESTRICTED_RESIZABILITY opt-out "won't apply when targeting API level 37"; the February 2026 blog confirms games stay exempt under Android 17.  
  Source: https://developer.android.com/about/versions/16/behavior-changes-16 (verified-primary-source)
- **Large-screen quality consequences on Play** — CONFIRMED. Not a submission blocker: "Play ranks apps and games optimized for large screens higher than unoptimized apps" and apps below the standard "display a warning on the app details page". Tier 3 (basic): the app "runs full screen ... The app is not letterboxed" and provides basic support for external input.  
  Source: https://developer.android.com/develop/adaptive-apps/guides/get-started-with-adaptive-apps (verified-primary-source)
- **Developer Program Policy in force and the WebView spam rule (ADDED)** — The full policy page is headed "(effective October 29, 2026, unless otherwise stated)". Webviews and Affiliate Spam: "We don't allow apps whose primary purpose is to drive affiliate traffic to a website or provide a webview of a website without permission from the website owner or administrator." The example is an app that "simply provides a webview of Google Shopping". A game whose HTML, JS and assets are bundled in the app is not a webview of a website; this reading is an inference from the policy text, which does not address bundled content explicitly.  
  Source: https://support.google.com/googleplay/android-developer/answer/18265346?hl=en (verified-primary-source)
- **Originality, impersonation and trademark rules that apply to a match-3 inspired by Candy Crush (ADDED)** — Repetitive Content: "We don't allow apps that merely provide the same experience as other apps already on Google Play"; violation example: "Copying content from other apps without adding any original content or value." Impersonation: "Be careful not to use app icons, descriptions, titles, or in-app elements that could mislead users about your app's relationship to someone else or another app"; violation example: "App titles and icons that are so similar to those of existing products or services that users may be misled." Trademark: "If your app uses another party's trademarks in a way that is likely to cause confusion, your app may be suspended." Limited Functionality: "We do not allow apps that only have limited functionality and content." Broken Functionality: "We don't allow apps that crash, force close, freeze, or otherwise function abnormally."  
  Source: https://support.google.com/googleplay/android-developer/answer/18265346?hl=en (verified-primary-source)
- **WebView without the INTERNET permission: default network blocking (ADDED, documented behaviour)** — YES, WebView works without INTERNET for local content; network loads are blocked by default. setBlockNetworkLoads: "If the application does not have the Manifest.permission.INTERNET permission, attempts to set a value of false will cause a SecurityException to be thrown. The default value is false if the application has the Manifest.permission.INTERNET permission, otherwise it is true." setAllowFileAccess: "Assets and resources are still accessible using file:///android_asset and file:///android_res." Never call setBlockNetworkLoads(false) in this app.  
  Source: https://developer.android.com/reference/android/webkit/WebSettings (verified-primary-source)
- **WebView without INTERNET: Chromium source confirms the mechanism (ADDED)** — AwSettings.java: "mBlockNetworkLoads = !hasInternetPermission;" and setBlockNetworkLoads throws SecurityException("Permission denied - application missing INTERNET permission"). net_helpers.cc: with ShouldBlockNetworkLoads() the request is NOT rejected for http(s); load flags become LOAD_ONLY_FROM_CACHE | LOAD_SKIP_CACHE_VALIDATION, and ShouldBlockURL only hard-blocks ftp. For file URLs: "Application's assets and resources are always available." In aw_proxying_url_loader_factory.cc, shouldInterceptRequest is still invoked after the flags are set and a non-null response is used as the override. So WebViewAssetLoader responses for https://appassets.androidplatform.net/ are served without INTERNET, while any real network fetch fails.  
  Source: https://chromium.googlesource.com/chromium/src/+/refs/heads/main/android_webview/browser/network_service/net_helpers.cc (verified-primary-source)
- **Recommended way to load bundled game content (ADDED)** — Page last updated 2026-11-10. "In-app content doesn't require internet access or consume a user's bandwidth." WebViewAssetLoader supports "Loading content with an HTTP(S) URL for compatibility with the same-origin policy"; example URL https://appassets.androidplatform.net/assets/index.html. "file:// URLs and data: URLs are considered to be opaque origins, meaning they can't take advantage of powerful web APIs such as fetch() or XMLHttpRequest." "we recommend against file://android_assets/ and file://android_res/ URLs." Google recommends setting setAllowFileAccessFromFileURLs and setAllowUniversalAccessFromFileURLs to false.  
  Source: https://developer.android.com/develop/ui/views/layout/webapps/load-local-content (verified-primary-source)
- **WebView diagnostic data upload and opt-out (ADDED, relevant to the no-data-collected claim)** — "WebView has the ability to upload anonymous diagnostic data to Google when the user gives their consent. Data is collected on a per-app basis for each app that instantiates a WebView. You can opt out of this feature" with <meta-data android:name="android.webkit.WebView.MetricsOptOut" android:value="true" /> inside <application>. ## Action items

- Deliver a signed release .aab (signed with an RSA 2048-bit or larger upload key in a .jks keystore) as the Play upload. Build an APK only for sideload testing and tell the user plainly that Play will not accept an APK for a new app.
- Set targetSdk to at least 36 (compileSdk 36 or 37; both platforms are stable in the SDK repository). Start versionCode at 1 and keep it below 2100000000.
- Set android:appCategory="game" on <application> and do not use the deprecated android:isGame. Choose Game in Play Console with a Puzzle or Casual category and at most five tags.
- Handle edge-to-edge insets in the Activity and WebView (no opt-out at API 36), and implement back handling with OnBackPressedDispatcher/OnBackInvokedCallback rather than onBackPressed or KEYCODE_BACK.
- Make the game layout adapt to any size and orientation and preserve state across configuration changes. The game exemption covers orientation locks, but large-screen quality still affects ranking and a PC listing is on by default for free games, so mouse and keyboard play must work.
- Load the game through androidx.webkit WebViewAssetLoader at https://appassets.androidplatform.net/assets/... with a shouldInterceptRequest override. Do not declare INTERNET, never call setBlockNetworkLoads(false), and keep setAllowFileAccess, setAllowFileAccessFromFileURLs and setAllowUniversalAccessFromFileURLs false.
- Bundle every asset locally (fonts, audio, images, scripts). Any external URL in the HTML will fail silently because network loads are blocked.
- Inspect the merged release manifest. If androidx.core 1.9 or newer is on the classpath, remove the DYNAMIC_RECEIVER_NOT_EXPORTED_PERMISSION <permission> and <uses-permission> nodes with tools:node="remove" (or avoid the dependency) so the permission list is truly empty.
- Add <meta-data android:name="android.webkit.WebView.MetricsOptOut" android:value="true" /> so the 'no data collected or shared' Data safety answer is clean.
- Ship an in-app Privacy Policy screen as bundled text (allowed by policy) and host the same policy on a public HTTPS web page (not a PDF) that names the app and developer, a privacy contact, and states that no data is collected, shared or retained. The user must supply or host this URL.
- Keep all native code out of the bundle (Kotlin/Java only) so 16 KB page-size and 64-bit requirements are met by default. Enable R8 shrinking as good practice; the 25% rule will not bind at this DEX size.
- Use an original name, icon, art, sounds and level content. Do not use 'Candy Crush', 'Saga', King characters, or look-alike icon and title. Do not mention or compare to any other game anywhere in the listing.
- Prepare listing assets to spec: 512x512 32-bit PNG icon, full square with no baked corners or shadow; 1024x500 feature graphic with no alpha; at least three 1080x1920 (or 1920x1080) real in-game screenshots with a clean status bar and no ranking, price or call-to-action text; title 30 characters or fewer; short description 80 or fewer with no emojis or all-caps.
- Write a Play Console checklist for the user: privacy policy URL, Ads = No, sign-in details = no restricted access, target audience, IARC content rating, Data safety = no data collected or shared, Financial features = none, Health = none, Government = no, News = no, Advertising ID = No if asked, trader status at account level, contact email.
- Decide the target audience deliberately. If the art is child-appealing, either include children and comply with the Families policy (the app already meets the technical parts) or tone the listing art so a 13+ declaration is credible.
- Tell the user up front that a personal account created after Nov 13, 2023 must complete device verification and run a 14-day closed test with 12 opted-in testers before applying for production, and that no build can guarantee approval.
- Test thoroughly on real devices and emulators (phone, tablet, Android 16 and 17) before upload; crashes, freezes or a blank WebView fall under the Broken Functionality policy and the pre-review checks.
